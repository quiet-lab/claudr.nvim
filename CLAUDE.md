# Инструкции для агентов

## Что это за репозиторий

claudr.nvim — плагин Neovim (Lua) для управления клиентами Claude Code
поверх работающего сервера herdr. Плагин — клиент сокета API herdr; процессами
агентов владеет herdr ([`docs/decisions/0001-herdr-owns-processes.md`](docs/decisions/0001-herdr-owns-processes.md)).
Источники данных — [`docs/data-sources.md`](docs/data-sources.md).

## Язык

- Общение с пользователем, документы, спецификации, комментарии, коммит-сообщения —
  по-русски, без калек с английского и без заимствований при наличии русского
  слова.
- Код и идентификаторы — по-английски. Технические термины (herdr, workspace,
  Claude Code, Neovim, pane как имя сущности API) — в оригинальном написании.
- В OpenSpec структурные заголовки и SHALL/MUST/MAY — по-английски, содержание —
  по-русски (поле `context` в `openspec/config.yaml`).

## Устройство кода

- Таймеры и опрос запрещены: всё делается по событиям — сокет herdr
  (`events.subscribe`), уведомления файловой системы (`vim.uv.new_fs_event`),
  выход процесса. Исключение обсуждается с пользователем до кода.
- Разбор внутренних форматов Claude Code (транскрипты, `meta.json`, записи
  фоновых задач) — в одном модуле; остальной код пользуется его результатом.
- Модель дерева отделена от отображения.

## Тесты

Тесты идут на двойнике сервера herdr и на образцах транскриптов, без живого
herdr и без живого Claude Code. Форматирование Lua — `stylua`.

## OpenSpec

- Изменение OpenSpec нужно, когда добавляется или меняется наблюдаемое
  поведение; дельта спецификации утверждается пользователем до кода и тестов.
- Перед правкой поведения сверяться со спецификацией: `openspec list --specs`,
  `openspec show <имя>`.
- Ход работы — только в `tasks.md` изменения; решение изменения — в его
  `design.md`, решение шире изменения — запись в `docs/decisions/`.
- Готовое изменение: `openspec validate <имя> --strict`, затем
  `openspec archive <имя> -y`.

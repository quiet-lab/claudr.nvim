# Инструкции для агентов

## Что это за репозиторий

claudr.nvim — плагин Neovim (Lua) для управления клиентами Claude Code
поверх работающего сервера herdr. Плагин — клиент сокета API herdr; процессами
агентов владеет herdr. Решения и причины — в `design.md` изменения OpenSpec,
поведение и форматы данных — в спецификациях `openspec/`.

## Язык

- Общение с пользователем, документы, спецификации, комментарии, коммит-сообщения —
  по-русски, без калек с английского и без заимствований при наличии русского
  слова.
- Код и идентификаторы — по-английски. Технические термины (herdr, workspace,
  Claude Code, Neovim, pane как имя сущности API) — в оригинальном написании.
- В OpenSpec структурные заголовки и SHALL/MUST/MAY — по-английски, содержание —
  по-русски (поле `context` в `openspec/config.yaml`).
- Репозиторий публичный: не записывать имена учётных записей, пути домашних
  каталогов и временных каталогов, идентификаторы сессий, названия рабочих
  проектов и компаний.

## Устройство кода

- Таймеры и опрос запрещены: всё делается по событиям — сокет herdr
  (`events.subscribe`), уведомления файловой системы (`vim.uv.new_fs_event`),
  выход процесса. Исключение обсуждается с пользователем до кода.
- Разбор внутренних форматов Claude Code (транскрипты, `meta.json`, записи
  фоновых команд) — в одном модуле (спецификация `claude-code-data`); остальной
  код пользуется его результатом.
- Модель дерева отделена от отображения.

## Тесты

Тесты идут на двойнике сервера herdr и на образцах транскриптов, без живого
herdr и без живого Claude Code. Проверки на живом сервере herdr при разработке
ведутся на отдельном сервере, не на рабочем. Форматирование Lua — `stylua`.

## OpenSpec

- Изменение OpenSpec нужно, когда добавляется или меняется наблюдаемое
  поведение; дельта спецификации утверждается пользователем до кода и тестов.
- Перед правкой поведения сверяться со спецификацией: `openspec list --specs`,
  `openspec show <имя>`.
- Ход работы — только в `tasks.md` изменения.
- Готовое изменение: `openspec validate <имя> --strict`, затем
  `openspec archive <имя> -y`. К архивации раздел «Open Questions» в `design.md`
  пуст.

## Документация

| Что | Где |
|---|---|
| Как пользоваться плагином: установка, настройка, команды, клавиши | `docs/` — только это |
| Поведение, включая форматы данных herdr и Claude Code | спецификации OpenSpec, проверяемыми требованиями |
| Решения и причины | `design.md` изменения, раздел «Decisions» |
| Нерешённое | раздел «Open Questions» в `design.md` |
| Отчёты и замеры | вне репозитория |

- Сведения о разработке в `docs/` не помещать; указатель — `docs/README.md`.
- Описание возможности для пользователя в `docs/` пишется вместе с самой
  возможностью (задача в `tasks.md` соответствующего этапа).
- Одно сведение — в одном месте; остальные документы ссылаются на него.

# Диалоги агента: ответ из Neovim

Когда агент Claude Code ждёт ответа (запрос разрешения, вопрос с вариантами, подтверждение
плана), плагин показывает запрос обычным буфером Neovim и отправляет ответ из него. Диалог в
панели при этом остаётся на экране и рабочим: ответить можно и там.

Структуру запроса плагину отдаёт хук Claude Code, поставляемый вместе с плагином
(каталог `claude-plugin/`). Экран панели плагин не читает и клавиши в панель для ответа не
отправляет.

## Установка хука

Хук ставится один раз в Claude Code как плагин:

```
claude plugin marketplace add <путь к клону claudr.nvim или quiet-lab/claudr.nvim>
claude plugin install claudr@claudr
```

То же из сессии Claude Code: `/plugin marketplace add …` и
`/plugin install claudr@claudr`. Marketplace из местного каталога читает плагин прямо из
клона. Обновление:

```
claude plugin marketplace update claudr
claude plugin update claudr@claudr
```

В записи хука задан срок (`timeout`) — сутки: запрос переживает обычный перерыв. После
срока хук завершается, запрос закрывается («закрыт хуком, ответ в панели»), диалог панели
остаётся рабочим.

Запрос виден плагину, только если Neovim с плагином был запущен до диалога и подключён к
тому же серверу herdr (`:Claudr tree`); запрос, начатый до запуска Neovim, виден только в
панели.

## Сокет и несколько экземпляров Neovim

Каждый экземпляр Neovim с плагином слушает сокет `$XDG_RUNTIME_DIR/claudr/<pid>.sock`
(без `XDG_RUNTIME_DIR` — каталог во временном каталоге системы; доступ только у владельца).
Сокет удаляется при выходе; сокеты умерших экземпляров удаляет следующий запуск. Хук
соединяется со всеми сокетами: запрос получают все экземпляры, первый ответ побеждает,
остальные видят «ответ принят другим экземпляром». Экземпляр принимает запрос, только если
он относится к его серверу herdr и к известной ему панели.

## Как открыть буфер диалога

| Способ | Действие |
|---|---|
| `d` в окне дерева | буфер диалога для ждущего запроса узла |
| `:Claudr dialog [узел]` | то же из командной строки |
| `d` в виде панели (наблюдение, история) | буфер диалога панели этого вида |

Клавиша вида настраивается: `dialogs.key` (`false` — не назначать). Если у узла несколько
ждущих запросов, предлагается выбор; в самом буфере `<Tab>` переходит к следующему запросу
панели. Узел панели учитывает и запросы своих субагентов.

Плагин сам окно и фокус не меняет: когда у панели с открытым видом агент переходит в
`blocked`, плагин только сообщает об этом и о команде открытия. Если ждущего запроса нет
(сессия без хука, диалог вне хука, например доверие каталогу), сообщение предлагает
подключение с вводом (`:Claudr attach`); см. [подключение к узлам](node-view.md).

В дереве узел показывает число ждущих запросов: `[ждут: 2]`.

## Буфер диалога

Буфер только для чтения, обычная навигация Vim, курсор на первом пункте. Ответ — Enter на
пункте.

| Клавиша | Действие |
|---|---|
| `<CR>` | выбрать пункт |
| `c` | подтвердить (множественный выбор, итоговый экран нескольких вопросов) |
| `T` | передать диалог терминалу |
| `<Tab>` | следующий ждущий запрос панели |
| `q` | закрыть буфер (запрос остаётся ждать) |
| `K`, `gd` | ссылки на файлы, см. [ссылки на файлы](file-references.md) |

Относительные пути в ссылках берутся от рабочего каталога запроса.

### Запрос разрешения

Показываются инструмент и содержимое: команда, либо файл и текст, либо вход инструмента.
Пункты по порядку:

1. разрешить один раз;
2. по пункту на каждое предложение Claude Code («разрешать всегда» и подобные), в порядке
   предложений; подпись собирается из данных предложения: что делает (правило с
   инструментом и содержимым, каталог, режим) и куда сохраняется — сессия, местные
   настройки проекта, настройки проекта или пользовательские настройки;
3. отказать;
4. отказать с пояснением;
5. отказать и прервать.

Пункта «перейти в режим auto» буфер не предлагает: среди предложений Claude Code такого
нет, он остаётся терминалу (`T`).

### Вопрос

- один выбор: Enter на варианте — ответ;
- пункт «свой ответ» (есть и в множественном выборе) открывает [окно ввода](message-input.md),
  текст уходит как есть, с переводами строк; в множественном выборе он заменяет отметки;
- множественный выбор: Enter отмечает и снимает отметку, `c` подтверждает отмеченные (без
  отметок ничего не отправляется); метки идут через «, » в порядке пунктов, а метка с
  запятой берётся в двойные кавычки (`"Cheese, aged", Olives`), как отвечает панель;
- несколько вопросов идут по очереди, затем итоговый экран со всеми ответами; подтверждение
  отправляет одно решение, «изменить ответ на вопрос N» возвращает к вопросу с сохранением
  ответов.

### План

Показывается текст плана; пункты: подтвердить, отказать с пояснением (правка плана),
отказать, отказать и прервать. Режим после подтверждения выбирает Claude Code.

### Отказы

«Отказать с пояснением» открывает окно ввода, пояснение уходит агенту; «отказать и прервать»
останавливает ход как Escape в панели. Те же отказы есть у всех видов диалога.

## Состояния буфера

После отправки пункты исчезают, буфер показывает «решение отправлено»; второе решение
отправить нельзя. Запрос, чей хук уже завершился после отправки решения, в число ждущих
на узле и в выбор запросов не входит. Затем состояние меняется по записям транскрипта:

| Состояние | Когда |
|---|---|
| решение принято Claude Code | в транскрипте появилось подтверждение решения хука либо результат вызова |
| отвечено в панели или другим клиентом | результат вызова появился без вашего решения |
| закрыт хуком, ответ в панели | хук завершился (Escape в панели, срок, выход сессии) |
| ответ принят другим экземпляром Neovim | ответил другой экземпляр |
| передан терминалу | команда `T` |

Если ответить в панели и в Neovim одновременно, побеждает панель, решение из Neovim
теряется без сообщения об ошибке; буфер при этом может показать «решение принято Claude
Code», так как судит по результату вызова.

## Совместная работа с хуками других плагинов

Claude Code запускает хуки одного события параллельно. Хук плагина ничего не блокирует и
чужим хукам не мешает:

- первое `allow` от другого хука исполняется сразу, не дожидаясь хука плагина; запрос в
  Neovim закрывается по результату вызова (состояние «отвечено в панели или другим
  клиентом»);
- `deny` из Neovim главнее `allow` другого хука, если решения поданы одновременно; если
  другой хук разрешил раньше, вызов уже исполнен;
- хуки других событий (`SessionStart`, `SessionEnd`, `Notification`, `Stop`) с хуком плагина
  не пересекаются;
- другой хук `PreToolUse` может изменить вход инструмента; тогда плагин может не найти
  вызов в транскрипте, и такой запрос закроют выход сессии, срок хука или команда `T`;
  решение из Neovim при этом отправляется как обычно.

## Терминал как запасной путь

`T` закрывает соединение запроса без решения, закрывает буфер и предлагает подключение с
вводом; диалог остаётся в панели обычным. Так же поступайте для сессий без хука и диалогов
вне хука. Правила отказа Claude Code проверяются и после вашего разрешения: вызов может быть
отклонён, об этом говорит результат вызова в панели.

Если сообщение агенту отправлено в миг появления диалога, herdr ещё может показывать
`working` и ответить ошибкой (`agent_prompt_lost`): окно ввода сохраняет текст, повторная
отправка после появления состояния `blocked` открывает буфер диалога.

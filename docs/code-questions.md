# Вопросы по коду

Вопрос по коду задаётся из буфера: плагин собирает контекст (файл, строки, выделение,
окружающую функцию, сведения языкового сервера) и отправляет его вместе с вопросом
отдельному процессу Claude Code. Ответ появляется в окне сбоку по мере генерации.

Каждый вопрос из буфера с кодом открывает новую **тему** — отдельную сессию Claude Code.
Тема не занимает панель herdr и не появляется в дереве. Продолжить тему можно из её окна
ответа: следующий вопрос уходит в ту же сессию, и Claude Code помнит прежний разговор.
Тему плагин сам не угадывает: новая тема — вопрос из буфера, продолжение — вопрос из окна
ответа.

Нужен Claude Code (`claude` в `PATH`). Сервер herdr для вопросов по коду не нужен.

## Команды

| Команда | Что делает |
|---|---|
| `:Claudr ask [режим]` | Вопрос по месту курсора: файл, строка, окружающая функция. Из окна ответа — продолжение его темы. |
| `:Claudr ask-selection [режим]` | Вопрос по последнему выделению: путь файла, диапазон строк и текст выделенных строк. |
| `:Claudr ask-file [режим]` | Вопрос по текущему файлу: в вопрос уходит содержимое буфера целиком, включая несохранённые правки. |
| `:Claudr topics` | Перечень тем текущего проекта; выбранная тема открывается. |
| `:Claudr topic-last` | Открыть тему проекта, к которой обращались последней. |

Текст вопроса вводится в строке ввода (`vim.ui.input`), перечень тем показывается списком
выбора (`vim.ui.select`); если у вас установлен плагин, заменяющий эти окна, используется он.
Без аргумента режима вопрос задаётся во встроенном режиме «вопрос по коду».

Команда `:Claudr` не принимает диапазон строк, поэтому из визуального режима удобнее
пользоваться клавишей `<Plug>(claudr-ask)` (см. ниже) или выйти из выделения и вызвать
`:Claudr ask-selection`.

## Клавиши

Своих глобальных клавиш плагин не назначает. Для назначения есть сопоставления `<Plug>`:

| Сопоставление | Режим | Что делает |
|---|---|---|
| `<Plug>(claudr-ask)` | normal | вопрос по месту курсора |
| `<Plug>(claudr-ask)` | visual | вопрос по выделенным строкам |
| `<Plug>(claudr-ask-file)` | normal | вопрос по текущему файлу |
| `<Plug>(claudr-topics)` | normal | перечень тем проекта |
| `<Plug>(claudr-topic-last)` | normal | последняя тема |

Пример:

```lua
vim.keymap.set({ "n", "x" }, "<leader>cq", "<Plug>(claudr-ask)")
vim.keymap.set("n", "<leader>cf", "<Plug>(claudr-ask-file)")
vim.keymap.set("n", "<leader>ct", "<Plug>(claudr-topics)")
vim.keymap.set("n", "<leader>cl", "<Plug>(claudr-topic-last)")
```

В окне ответа (normal):

| Клавиша | Что делает |
|---|---|
| `a` | задать следующий вопрос в этой теме |
| `<CR>`, `gf` | перейти по ссылке `файл:строка` под курсором |
| `R` | повторить вопрос, на котором произошла ошибка, без повторного ввода |
| `q` | закрыть окно ответа |

## Окно ответа

Окно ответа открывается справа; у каждой темы своё окно, окна нескольких тем делят правую
колонку. Окно только для чтения: в нём заголовок темы, вопросы и ответы. Вызовы
инструментов и служебные сообщения Claude Code в ответ не попадают — показывается только
текст ответа.

Ссылка вида `lua/foo.lua:42` в ответе открывается переходом: файл открывается в окне
редактирования (не в окне ответа) на указанной строке. Относительный путь отсчитывается от
каталога проекта темы.

Если процесс не запустился (например, `claude` не найден) или оборвался до конца ответа,
окно показывает полученную часть ответа и причину. Вопрос сохраняется: `R` отправляет его
снова.

Пока тема отвечает, новый вопрос в ней встаёт в очередь (в окне — «Вопрос (в очереди)») и
уходит после окончания ответа; вопросы очереди уходят по одному, в порядке постановки.
Разные темы отвечают одновременно, каждая в своём окне.

## Темы

Плагин запоминает каждую тему в файле `claudr/topics.json` каталога состояния Neovim
(`:echo stdpath("state")`): сессию, каталог проекта, заголовок (начало первого вопроса),
режим, файл и функцию, откуда задан вопрос, время создания и последнего обращения. Список
переживает перезапуск Neovim.

Содержимое закрытой темы берётся из транскрипта её сессии в каталоге данных Claude Code:
окно восстанавливается без нового запроса к модели. Claude Code удаляет старые транскрипты
(настройка `cleanupPeriodDays`, по умолчанию 30 дней); тема без транскрипта остаётся в
перечне с пометкой «содержимое недоступно».

Каталог проекта — корень репозитория git, найденный от файла буфера; если файл не в
репозитории, — текущий рабочий каталог Neovim. Процесс Claude Code запускается в этом
каталоге, перечень тем показывает темы этого проекта. Темы не смешиваются с историей сессий
(см. [историю сессий](history.md)).

## Настройки

Раздел `code_questions` в `require("claudr").setup({...})`:

```lua
require("claudr").setup({
  code_questions = {
    model = "sonnet",
    fork_from_base = false,
    -- mcp = { mcpServers = { docs = { command = "docs-server", args = { "--stdio" } } } },
  },
})
```

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `model` | `"sonnet"` | Модель, которая отвечает на вопросы (имя или псевдоним модели Claude Code). Режим может задать свою. |
| `mcp` | не задана | Источник знаний — MCP-сервер проекта (см. ниже). |
| `fork_from_base` | `false` | Ответвление новой темы от базовой сессии проекта. В этой версии не поддерживается (см. ниже). |

Отвечающий процесс получает только инструменты чтения (`Read`, `Grep`, `Glob`), если режим
не задаёт другого набора.

### Источник знаний

Источник знаний — необязательный MCP-сервер (например, сервер документации проекта),
который отвечающий процесс получает при запуске. Без него вопросы по коду работают как
обычно. Значение `mcp` — одно из:

- описание в формате `--mcp-config` Claude Code, общее для всех проектов:
  `{ mcpServers = { <имя> = { command = …, args = {…} } } }`;
- таблица «каталог проекта → описание»:
  `{ ["/путь/к/проекту"] = { mcpServers = {…} } }`;
- функция `function(project_dir) return описание или nil end`.

Процесс получает только серверы источника знаний (другие серверы MCP из настроек Claude Code
не подключаются), и их инструменты разрешены.

### Ответвление от базовой сессии

Ответвление новой темы от базовой сессии проекта в этой версии не поддерживается. Каждая
тема — новая сессия Claude Code. Если задать `fork_from_base = true`, тема всё равно
начинается новой сессией, а плагин один раз за сеанс Neovim предупреждает, что ответвление
не поддерживается.

## Точки расширения

### Режимы

Режим — именованный набор: наставление агенту (добавляется к системному запросу Claude
Code), модель и набор инструментов. Встроенный режим один — `code` («вопрос по коду»). Свой
режим регистрируется так:

```lua
require("claudr.questions").register_mode("review", {
  desc = "разбор изменений",
  prompt = "Отвечай как рецензент: ищи ошибки и неочевидные места.",
  model = "opus",            -- необязательно; без него — настройка model
  tools = { "Read", "Grep" }, -- необязательно; без него — инструменты чтения
})
```

Вопрос в этом режиме: `:Claudr ask review` (имена режимов дополняются по `<Tab>`).
Наставление режима в пределах темы не меняется: продолжение темы идёт в её режиме.

### Поставщики контекста

Поставщик контекста — функция, которая по буферу и выделению возвращает пакет контекста.
Встроенный общий поставщик даёт файл, строки, выделенный текст, окружающий узел tree-sitter
(обычно функцию или класс и её имя) и, если к буферу подключён языковой сервер, определение
и описание символа. Без языкового сервера пакет собирается без них.

Дополнительный поставщик регистрируется для типа файла и дополняет пакет общего:

```lua
require("claudr.questions").register_provider("lua", function(req, packet)
  -- req: { bufnr, kind = "cursor"|"selection"|"file", range, cursor, project_dir }
  -- packet: пакет общего поставщика (file, filetype, lines, text, content, node, symbol,
  --         definition, hover)
  return { runtime = "LuaJIT" }
end)
```

Возвращённые поля добавляются к пакету и уходят в вопрос строками «поле: значение».

## ADDED Requirements

### Requirement: Путь сокета
Клиент MUST подключаться к сокету API herdr по пути из `HERDR_SOCKET_PATH`, без этой переменной — по сокету herdr по умолчанию (`herdr.sock` в каталоге конфигурации herdr).

#### Scenario: Neovim запущен внутри панели herdr
- **WHEN** в окружении задан `HERDR_SOCKET_PATH`
- **THEN** клиент подключается по этому пути, а не по пути по умолчанию

#### Scenario: Neovim запущен вне herdr
- **WHEN** `HERDR_SOCKET_PATH` не задана
- **THEN** клиент подключается к сокету по умолчанию

### Requirement: Кадры и соответствие ответов
Клиент MUST обмениваться с сервером строками JSON, по одному объекту в строке. Запрос MUST иметь вид `{"id","method","params"}`, ответ — содержать `id` запроса и `result` либо `error`. Ответ с `error` MUST попадать вызвавшему как ошибка с кодом и текстом сервера. Несколько запросов MAY быть в полёте одновременно.

#### Scenario: Ответы приходят не по порядку
- **WHEN** клиент отправил два запроса подряд, а сервер ответил сначала на второй
- **THEN** каждый вызвавший получает ответ на свой запрос

#### Scenario: Ошибка сервера
- **WHEN** сервер отвечает `{"id":…,"error":{"code":"not_found","message":"pane not found"}}`
- **THEN** вызвавший получает ошибку с кодом `not_found` и текстом сервера

### Requirement: Идентификаторы — строки
Идентификаторы workspace, вкладок и панелей (например, `w1`, `w1:t1`, `w1:p1`) MUST обрабатываться как строки: числовой вид не гарантирован, в номерах бывают буквы. Клиент MUST NOT приводить их к числам.

#### Scenario: Идентификатор с буквой
- **WHEN** сервер присылает идентификатор панели, в котором есть буква
- **THEN** клиент хранит и передаёт его как строку без изменений

### Requirement: Проверка версии протокола
После подключения клиент MUST выполнить `ping`, ответ которого несёт версию протокола, и сравнить её с минимально поддерживаемой (22). Сервер с меньшим номером MUST отвергаться с сообщением, где названы найденный и требуемый номера; сервер с большим номером MUST приниматься, неизвестные поля ответов MUST игнорироваться.

#### Scenario: Старый сервер
- **WHEN** `ping` возвращает протокол 21
- **THEN** клиент не загружает дерево и сообщает, что требуется протокол 22 и новее, а найден 21

#### Scenario: Новый сервер
- **WHEN** `ping` возвращает протокол 23 и поля, которых клиент не знает
- **THEN** клиент работает, лишние поля игнорируются

### Requirement: Состав снимка
Клиент MUST читать `session.snapshot` и использовать из него workspace (`workspace_id`, `parent_workspace_id`, `label`, `number`, `agent_status`, `active_tab_id`), вкладки (`tab_id`, `workspace_id`, `label`, `number`) и панели (`pane_id`, `tab_id`, `workspace_id`, `foreground_process`, `cwd`, `agent`, `display_agent`, `agent_status`, `terminal_title`, `revision`, `agent_session`). Состояния агента: `idle`, `working`, `blocked`, `done`, `unknown`.

#### Scenario: Сессия агента
- **WHEN** у панели `agent_session` содержит `kind`, `agent` и `value`
- **THEN** клиент отдаёт `value` как идентификатор сессии Claude Code для панели с `agent = "claude"`

#### Scenario: Неизвестное состояние
- **WHEN** сервер присылает состояние агента, которого клиент не знает
- **THEN** клиент передаёт его как есть, ошибки нет

### Requirement: Снимок и подписка
Клиент MUST сначала открыть подписку `events.subscribe` на отдельном соединении и дождаться ответа `subscription_started`, затем запросить `session.snapshot` другим соединением. События MUST служить сигналом перечитать состояние: содержимое событий MUST NOT накладываться на снимок как данные. Перечитывания MUST выполняться по одному; событие, пришедшее во время чтения, MUST вызывать ещё одно.

#### Scenario: Событие во время чтения снимка
- **WHEN** во время выполнения `session.snapshot` приходит `pane.created`
- **THEN** после получения снимка клиент запрашивает снимок ещё раз, и итоговое состояние содержит новую панель

#### Scenario: Занятое соединение подписки
- **WHEN** подписка открыта и нужно выполнить запрос
- **THEN** запрос идёт другим соединением, соединение подписки остаётся занятым событиями

### Requirement: События жизненного цикла
Клиент MUST подписываться без параметров на события жизненного цикла workspace, вкладок и панелей (`workspace.*`, `tab.*`, `pane.created`, `pane.updated`, `pane.closed`, `pane.exited`, `pane.agent_detected`, `layout.updated`). Клиент MUST принимать названия таких событий в обоих написаниях: через точку и через подчёркивание (`pane_closed`).

#### Scenario: Событие через подчёркивание
- **WHEN** приходит событие `pane_exited` с `pane_id`
- **THEN** клиент обрабатывает его так же, как `pane.exited`

#### Scenario: Событие через точку
- **WHEN** приходит `{"event":"pane.closed","data":{"pane_id":…}}`
- **THEN** клиент помечает кэш устаревшим и перечитывает состояние

### Requirement: Подписки по панелям
Подписки, привязанные к панели (`pane.output_changed`, `pane.agent_status_changed`), MUST создаваться только для панелей из последнего снимка. Одна неверная запись подписки отклоняет весь запрос, поэтому клиент MUST пересобирать подписки по событиям `pane.created` и `pane.closed`.

#### Scenario: Закрытие панели
- **WHEN** приходит `pane.closed` для панели с подпиской
- **THEN** клиент открывает подписку заново без этой панели, остальные подписки продолжают действовать

#### Scenario: Новая панель
- **WHEN** приходит `pane.created`
- **THEN** подписки включают новую панель после следующего снимка

### Requirement: Чтение панели
Клиент MUST читать вывод панели методом `pane.read` (`pane_id`, источник, формат); ответ несёт `text`, `revision` и `truncated`. Источник `recent_unwrapped` MUST применяться для видов, показывающих вывод целиком.

#### Scenario: Чтение вывода
- **WHEN** вид запрашивает вывод панели
- **THEN** клиент вызывает `pane.read` с источником `recent_unwrapped` и отдаёт `text` и `revision`

### Requirement: Потеря событий
Получив от сервера ошибку `events_lost`, клиент MUST считать кэш устаревшим, открыть новую подписку, дождаться `subscription_started`, запросить `session.snapshot` другим соединением и заменить кэш снимком.

#### Scenario: Отставший читатель
- **WHEN** сервер присылает `events_lost` и закрывает соединение подписки
- **THEN** клиент без вмешательства пользователя подписывается заново и обновляет дерево по новому снимку

### Requirement: Недоступный сервер
Если сервер недоступен (сокета нет или соединение отвергнуто), клиент MUST сообщить об этом состоянием «нет сервера», видимым подписчикам модели, и MUST NOT завершаться ошибкой при загрузке плагина. Действие, требующее сервера, MUST завершаться понятным сообщением.

#### Scenario: Запуск без сервера
- **WHEN** Neovim запущен, а сервера herdr нет
- **THEN** плагин загружается, дерево показывает состояние «нет сервера», команды запуска и сообщений сообщают, что сервер недоступен

### Requirement: Перезапуск сервера
Клиент MUST переподключаться по событию файловой системы в каталоге сокета (появление сокета, `vim.uv.new_fs_event`), а не по расписанию. После подключения к новому серверу клиент MUST выполнить проверку протокола, подписку и снимок заново; прежнее дерево MUST заменяться новым без перезапуска Neovim.

#### Scenario: Подмена сервера
- **WHEN** соединение рвётся и в каталоге сокета появляется новый сокет
- **THEN** клиент подключается к нему, дерево обновляется по новому снимку

#### Scenario: Сервер запущен после Neovim
- **WHEN** Neovim работал без сервера и сервер herdr запускается
- **THEN** появление сокета вызывает подключение, дерево заполняется

### Requirement: Отсутствие таймеров и опроса
Клиент MUST NOT использовать таймеры, периодические проверки и повторные попытки по расписанию: переподключение, перечитывание и ожидание ответов идут по событиям (сокет, файловая система, выход процесса).

#### Scenario: Сервер недоступен длительное время
- **WHEN** сервера нет и сокета нет
- **THEN** клиент не выполняет ни одной попытки подключения, пока в каталоге сокета не произойдёт событие

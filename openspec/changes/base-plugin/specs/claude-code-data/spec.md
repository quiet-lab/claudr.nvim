## ADDED Requirements

### Requirement: Единый модуль чтения данных Claude Code
Все данные Claude Code (транскрипты, `meta.json` субагентов, записи фоновых команд, файлы вывода) MUST читаться одним модулем. Остальной код MUST получать от него записи видов «субагент», «фоновая команда» и «реплика диалога» и MUST NOT разбирать эти форматы сам.

#### Scenario: Изменение формата
- **WHEN** Claude Code меняет запись транскрипта
- **THEN** правка ограничивается модулем чтения, а дерево, виды и перечни получают те же виды записей

### Requirement: Поиск транскрипта сессии
Транскрипт сессии MUST находиться по идентификатору сессии как файл `<идентификатор>.jsonl` в каталоге проекта среди каталогов `projects/` данных Claude Code. Каталог проекта MUST NOT выводиться из `cwd` панели: в сессии мог меняться рабочий каталог.

#### Scenario: Сессия сменила каталог
- **WHEN** `cwd` панели не совпадает с каталогом, по которому назван каталог проекта сессии
- **THEN** транскрипт находится по идентификатору среди всех каталогов проектов

#### Scenario: Транскрипта нет
- **WHEN** файла с таким идентификатором нет ни в одном каталоге проекта
- **THEN** модуль сообщает, что транскрипт не найден, и не возвращает записей

### Requirement: Чтение транскрипта
Транскрипт MUST читаться как последовательность записей JSON, по одной в строке. Дописываемый транскрипт MUST читаться с запомненного смещения: уже прочитанные записи не разбираются повторно, незавершённая последняя строка ждёт завершения.

#### Scenario: Дописывание
- **WHEN** в транскрипт дописаны две записи после прочитанной части
- **THEN** модуль возвращает только эти две записи

#### Scenario: Недописанная строка
- **WHEN** последняя строка файла не закончена переводом строки
- **THEN** она не разбирается, пока не будет дописана

### Requirement: Реплики диалога
Модуль MUST выделять из транскрипта реплики пользователя и агента в порядке записи; каждая реплика несёт автора и текст. Служебные записи, не являющиеся репликами, в диалог MUST NOT входить.

#### Scenario: Диалог сессии
- **WHEN** в транскрипте записи пользователя, ответа агента и служебная запись
- **THEN** модуль возвращает две реплики в порядке записи

### Requirement: Субагенты сессии
Субагенты сессии MUST определяться по парам `agent-<id>.jsonl` и `agent-<id>.meta.json` в каталоге `subagents/` каталога сессии. Из `meta.json` модуль MUST читать `agentType`, `description`, `toolUseId`, `spawnDepth`, `parentAgentId`, `model` и `finished`. Посторонние файлы каталога (например, `*.forked-skill.json`) MUST игнорироваться.

#### Scenario: Пара файлов
- **WHEN** в `subagents/` лежат `agent-a1.jsonl` и `agent-a1.meta.json`
- **THEN** модуль возвращает субагента `a1` с полями из `meta.json`

#### Scenario: Посторонний файл
- **WHEN** в `subagents/` лежит файл `agent-a1.forked-skill.json`
- **THEN** он не даёт субагента

### Requirement: Вложенность субагентов
Субагенты всех уровней MUST лежать в одном каталоге `subagents/` сессии-владельца. Родитель MUST определяться полем `parentAgentId`; у субагента первого уровня поля нет.

#### Scenario: Вложенный субагент
- **WHEN** `meta.json` субагента B содержит `parentAgentId`, равный идентификатору субагента A
- **THEN** модуль возвращает B как дочернего субагента A, а A — как субагента первого уровня

### Requirement: Отметка завершения субагента
Субагент MUST считаться завершённым при `finished: true` в `meta.json`. У работающего субагента поля `finished` нет: его отсутствие MUST читаться как «отметки завершения нет», а не как ошибка.

#### Scenario: Работающий субагент
- **WHEN** в `meta.json` нет поля `finished`
- **THEN** модуль возвращает субагента без отметки завершения

#### Scenario: Завершённый субагент
- **WHEN** в `meta.json` записано `finished: true`
- **THEN** модуль возвращает субагента с отметкой завершения

### Requirement: Запуск фоновой команды
Фоновой командой MUST считаться вызов инструмента Bash с `run_in_background: true` в транскрипте владельца (сессии или субагента). Из вызова модуль MUST брать `command` и `description`, из результата вызова — `backgroundTaskId` и путь файла вывода. Команда MUST принадлежать тому владельцу, в чьём транскрипте записан вызов.

#### Scenario: Команда субагента
- **WHEN** вызов с `run_in_background: true` записан в транскрипте субагента
- **THEN** модуль возвращает команду как принадлежащую этому субагенту

#### Scenario: Результат вызова
- **WHEN** в результате вызова есть `backgroundTaskId` и путь файла вывода
- **THEN** команда содержит идентификатор задачи и этот путь

### Requirement: Завершение фоновой команды
Завершением фоновой команды MUST считаться запись с блоком `<task-notification>`, содержащим `task-id` команды. Из блока модуль MUST читать `task-id`, `tool-use-id`, `output-file`, `status` и код выхода из `summary`.

#### Scenario: Команда завершилась
- **WHEN** в транскрипте появляется `<task-notification>` с `task-id` команды, `status` и кодом выхода 0 в `summary`
- **THEN** команда получает отметку завершения со статусом и кодом выхода 0

#### Scenario: Чужое уведомление
- **WHEN** `task-id` уведомления не совпадает ни с одной известной командой
- **THEN** запись пропускается, ошибки нет

### Requirement: Состояние «оборван»
Субагент или фоновая команда без отметки завершения MUST получать состояние «оборван», когда модулю сообщено, что панель владельца завершила процесс или закрыта. Правило общее для субагентов и команд, в том числе вложенных.

#### Scenario: Владелец упал
- **WHEN** у субагента нет отметки завершения и сообщено, что панель владельца закрыта
- **THEN** субагент и его фоновые команды без отметки завершения оборваны

#### Scenario: Владелец жив
- **WHEN** отметки завершения нет, а панель владельца жива
- **THEN** узел остаётся работающим

### Requirement: Слежение за изменениями
Изменения каталога сессии, `subagents/`, транскриптов и файлов вывода MUST отслеживаться уведомлениями файловой системы (`vim.uv.new_fs_event`). Пока каталога `subagents/` нет, MUST наблюдаться каталог сессии; когда `subagents/` создан, наблюдение MUST переходить на него.

#### Scenario: Первый субагент
- **WHEN** у сессии не было каталога `subagents/`, и он создаётся
- **THEN** наблюдение переходит на него, а подписчики получают нового субагента

### Requirement: Устойчивость к неизвестному
Неизвестные виды записей, неизвестные поля и непонятные значения известных полей MUST пропускаться без ошибки; повреждённая строка транскрипта MUST пропускаться, остальные записи читаться.

#### Scenario: Новое поле
- **WHEN** в `meta.json` или записи транскрипта есть поле, которого модуль не знает
- **THEN** поле игнорируется, остальные данные читаются

#### Scenario: Неизвестная запись
- **WHEN** в транскрипте запись неизвестного вида
- **THEN** она пропускается, чтение продолжается

### Requirement: Отсутствие таймеров и опроса
Модуль MUST NOT использовать таймеры и периодическое чтение: каждое чтение вызвано уведомлением файловой системы или запросом подписчика.

#### Scenario: Файлы не меняются
- **WHEN** уведомлений файловой системы нет
- **THEN** модуль не читает файлы

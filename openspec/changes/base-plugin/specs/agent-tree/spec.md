## ADDED Requirements

### Requirement: Состав дерева
Дерево MUST содержать все workspace сервера herdr с вложенностью по `parent_workspace_id`, в каждом workspace — его вкладки, в каждой вкладке — её панели, в порядке `number`. Панели MUST входить в дерево независимо от того, кем они созданы, в том числе панели и вкладки, открытые агентами в отдельных вкладках и workspace.

#### Scenario: Вложенный workspace
- **WHEN** в снимке workspace `w2` имеет `parent_workspace_id` равный `w1`
- **THEN** `w2` находится в дереве под `w1`

#### Scenario: Агент открыл новую вкладку
- **WHEN** агент в панели создаёт вкладку и запускает в ней другого агента
- **THEN** вкладка и её панель с агентом появляются в дереве без действий пользователя

### Requirement: Виды панелей
Панель MUST быть узлом одного из двух видов: «агент» (в снимке задан `agent`) или «команда» (агента нет). Подпись панели с агентом MUST содержать `display_agent` (при отсутствии — `agent`) и заголовок терминала, панели с командой — `foreground_process` и `cwd`.

#### Scenario: Панель с командой
- **WHEN** в панели без агента работает `cargo` в каталоге `/src`
- **THEN** узел имеет вид «команда» и подпись с `cargo` и `/src`

#### Scenario: Панель с агентом
- **WHEN** в снимке у панели `agent = "claude"` и `display_agent = "opus"`
- **THEN** узел имеет вид «агент», подпись содержит `opus` и заголовок терминала

### Requirement: Состояние панели с агентом
Узел панели с агентом MUST показывать состояние `agent_status` из herdr (`idle`, `working`, `blocked`, `done`, `unknown`) и MUST менять его по событию `pane.agent_status_changed`.

#### Scenario: Агент ждёт ответа
- **WHEN** приходит `pane.agent_status_changed` с `agent_status = blocked`
- **THEN** узел панели показывает состояние `blocked`

### Requirement: Субагенты панели
Под узлом панели с агентом Claude Code MUST находиться субагенты его сессии. Транскрипт сессии MUST находиться по `agent_session.value` среди каталогов `~/.claude/projects/`, субагенты — по файлам `subagents/agent-<id>.meta.json` этой сессии. Субагент первого уровня MUST быть дочерним узлом панели, вложенный (с `parentAgentId`) — дочерним узлом своего родителя. Подпись субагента MUST содержать `description` и `agentType`.

#### Scenario: Вложенные субагенты
- **WHEN** в каталоге `subagents/` лежат `meta.json` субагента A и субагента B с `parentAgentId`, равным идентификатору A
- **THEN** B находится под A, A — под панелью владельца

### Requirement: Панель без известной сессии
Панель, для которой транскрипт не найден или `agent_session` не задан, MUST показываться без субагентов и фоновых команд; когда сессия становится известна (`pane.updated`), они MUST появляться. Панели с агентом не Claude Code MUST показываться без субагентов и фоновых команд.

#### Scenario: Сессия ещё не известна
- **WHEN** у панели нет `agent_session`
- **THEN** узел панели показывается без дочерних узлов, а после `pane.updated` с заполненным `agent_session` дерево получает субагентов сессии

#### Scenario: Агент не Claude Code
- **WHEN** в панели работает агент другого вида
- **THEN** узел панели показывается без субагентов и фоновых команд

### Requirement: Фоновые команды
Под узлом владельца (панели с агентом или субагента) MUST находиться его фоновые команды. Команда MUST определяться записью вызова инструмента Bash с `run_in_background: true` в транскрипте владельца; идентификатор задачи и путь файла вывода MUST браться из `toolUseResult.backgroundTaskId` и результата вызова. Подпись команды MUST содержать `description` (при отсутствии — `command`). Фоновые команды вложенных субагентов MUST находиться под своим субагентом.

#### Scenario: Команда агента
- **WHEN** в транскрипте владельца есть вызов Bash с `run_in_background: true` и результат с `backgroundTaskId`
- **THEN** под узлом владельца есть узел команды с подписью из `description`

#### Scenario: Команда субагента
- **WHEN** вызов с `run_in_background: true` записан в транскрипте субагента
- **THEN** узел команды находится под узлом этого субагента, а не под панелью

### Requirement: Состояния субагентов
Субагент MUST иметь одно из состояний «работает», «завершён», «оборван». Субагент считается завершённым при `finished: true` в `meta.json`, работающим — пока `finished` не записано (у работающего субагента поля нет) и владелец жив.

#### Scenario: Работающий субагент
- **WHEN** в `meta.json` субагента нет поля `finished`, а панель владельца жива
- **THEN** состояние субагента «работает»

#### Scenario: Завершённый субагент
- **WHEN** в `meta.json` записано `finished: true`
- **THEN** состояние субагента «завершён»

#### Scenario: Завершённый узел остаётся
- **WHEN** субагент завершён, а панель владельца жива
- **THEN** узел остаётся в дереве с состоянием «завершён»

### Requirement: Состояния фоновых команд
Фоновая команда MUST иметь одно из состояний «работает», «завершён», «оборван». Команда считается завершённой при записи `<task-notification>` с её `task-id`; код выхода из `summary` MUST показываться в подписи. Пока записи нет и владелец жив, команда работает.

#### Scenario: Завершение фоновой команды
- **WHEN** в транскрипте после вызова появляется `<task-notification>` с `task-id` команды и кодом выхода 0 в `summary`
- **THEN** состояние команды «завершён» и подпись содержит код выхода 0

### Requirement: Оборванные узлы
Субагент и фоновая команда без отметки завершения, панель владельца которых закрыта или завершила процесс (`pane.closed`, `pane.exited`), MUST получать состояние «оборван». Правило действует одинаково для субагентов и фоновых команд, в том числе вложенных.

#### Scenario: Упавший владелец
- **WHEN** у субагента нет `finished` и приходит `pane.exited` панели владельца
- **THEN** субагент и все его невыполненные фоновые команды получают состояние «оборван»

### Requirement: Обновление по событиям
Дерево MUST обновляться по событиям: структура и состояния панелей — по событиям herdr, субагенты и фоновые команды — по уведомлениям файловой системы об изменении каталога сессии, `subagents/` и транскриптов (`vim.uv.new_fs_event`). Пока каталога `subagents/` нет, MUST наблюдаться каталог сессии.

#### Scenario: Новый субагент
- **WHEN** сессия запускает субагента и в `subagents/` появляются его `meta.json` и транскрипт
- **THEN** узел субагента появляется в дереве без действий пользователя

#### Scenario: Первый субагент сессии
- **WHEN** у сессии не было каталога `subagents/`, и он создаётся
- **THEN** наблюдение переходит на него и узел первого субагента появляется в дереве

### Requirement: Отсутствие таймеров и опроса в дереве
Дерево MUST NOT использовать таймеры и периодическое чтение: каждое изменение узла вызвано событием herdr, уведомлением файловой системы или выходом процесса.

#### Scenario: Ничего не происходит
- **WHEN** событий herdr и файловой системы нет
- **THEN** плагин не читает ни сокет, ни файлы Claude Code

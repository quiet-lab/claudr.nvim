## Context

herdr уже владеет процессами агентов и даёт API сокета; Claude Code пишет
транскрипты, `meta.json` субагентов и файлы вывода фоновых команд. Плагин
собирает из этих двух источников единое дерево и работает с узлами из Neovim.
Источники и форматы — [`docs/data-sources.md`](../../../docs/data-sources.md);
выбор «процессами владеет herdr» —
[`docs/decisions/0001-herdr-owns-processes.md`](../../../docs/decisions/0001-herdr-owns-processes.md).
Устройство должно допускать наращивание возможностей: новые виды узлов и
действия добавляются без переделки клиента и модели.

## Goals / Non-Goals

**Goals:**

- Дерево всех workspace, вкладок, панелей, субагентов и фоновых команд.
- Подключение к любому узлу, сообщения агентам, запуск сессий, история, вопросы по коду.
- Всё обновляется по событиям.

**Non-Goals:**

- Запуск и владение процессами агентов (это herdr).
- Запись в субагентов и фоновые команды.
- Выбор библиотеки интерфейса и механизма вопросов по коду.

## Decisions

### D1. Клиент сокета на Lua через `vim.uv`, без промежуточного демона

Плагин сам открывает Unix-сокет (`vim.uv.new_pipe`), разбирает строки NDJSON и
сопоставляет ответы запросам по `id`. Отдельного процесса-посредника нет:
состояние живёт в Neovim, второй источник правды не появляется. Подписка
держит отдельное соединение, остальные запросы идут другим; снимок после
подписки берётся другим соединением ([`docs/data-sources.md`](../../../docs/data-sources.md),
раздел «Подписка»).

### D2. События — сигналы перечитывания

Снимок и события не имеют общей последовательности, поэтому события не
накладываются на снимок: они помечают кэш устаревшим и запускают перечитывание
(`session.snapshot`, `pane.read`). Перечитывания сериализуются; событие,
пришедшее во время чтения, вызывает ещё одно.

### D3. Подписки по панелям пересобираются

Подписки `pane.output_changed` и `pane.agent_status_changed` задаются на
конкретную панель, а подписка на несуществующую панель отвергает весь запрос.
Плагин держит общую подписку на события жизненного цикла и пересобирает
подписки по панелям при `pane.created`, `pane.closed`.

### D4. Единый модуль разбора форматов Claude Code

Транскрипты, `meta.json`, записи вызовов фоновых команд и `task-notification`
разбирает один модуль; остальной код получает от него записи вида «субагент»,
«фоновая команда», «реплика диалога». Если формат Claude Code изменится,
правится один модуль. События хуков `SubagentStart` и `SubagentStop` — запасной
источник на этот случай, в базовый набор не входят.

### D5. Слежение за файлами без опроса

Каталог сессии, `subagents/`, транскрипты и файлы вывода отслеживаются
`vim.uv.new_fs_event`; дописываемые файлы читаются с запомненного смещения.
Пока каталога `subagents/` нет, наблюдается каталог сессии, затем наблюдение
переходит на `subagents/`. Каталог проекта сессии находится по идентификатору
среди каталогов `~/.claude/projects/`.

### D6. Состояние «оборван»

Отметки завершения у упавшего владельца нет. Узел без отметки завершения
получает состояние «оборван», когда панель владельца закрыта или завершила
процесс (`pane.exited`, `pane.closed`). Правило общее для субагентов и
фоновых команд, включая вложенные.

### D7. Модель дерева отдельно от отображения

Модель — узлы с видом, подписью, состоянием, родителем и действиями; она
строится из снимка herdr и записей модуля разбора и обновляется по событиям.
Отображение подписывается на изменения модели. Новая возможность добавляется
новым видом узла или действием, без правки клиента. Библиотека интерфейса
не выбрана.

### D8. Подключение к узлу зависит от вида узла

Панель с агентом — живой терминал (`herdr agent attach` в буфере терминала
Neovim); панель с командой — `pane.read` с обновлением по `pane.output_changed`;
субагент — транскрипт, фоновая команда — файл вывода, оба только для чтения.

### D9. Запуск сессии

Новая вкладка — `tab.create` (ответ несёт `root_pane`), деление —
`pane.split`; затем `agent.start` с видом `claude` в созданной панели.
Рабочий каталог плагин не передаёт, действует значение по умолчанию herdr.
`agent.start` ждёт готовности агента на стороне сервера, Neovim остаётся
отзывчивым: вызов асинхронный.

### D10. Выборы на развилках

- Узлы-контейнеры при подключении: вкладка — вид её первой панели, workspace —
  первой панели его активной вкладки; решение временное, см. открытый вопрос
  ниже.
- Завершённые узлы остаются в дереве с состоянием «завершён»; сворачивание и
  скрытие не определены, см. открытый вопрос ниже.
- Агенты не Claude Code (поле `agent` панели) показываются как панели с агентом
  без субагентов и фоновых команд: их файлов плагин не разбирает.
- Для субагентов и фоновых команд видимого в API herdr идентификатора панели
  нет: их идентификатор — `<панель владельца>/<идентификатор субагента или задачи>`.

## Библиотеки интерфейса

В конфигурации пользователя доступны snacks.nvim, nui.nvim и plenary.nvim;
выбор — открытый вопрос.

## Risks / Trade-offs

- Форматы файлов Claude Code не документированы и могут измениться → единый
  модуль разбора, образцы транскриптов в тестах, запасной источник — хуки.
- Зависимость от API форка herdr (протокол 22) → проверка протокола при
  подключении, отказ с понятным сообщением.
- Невозможность структурированно писать субагентам → осознанная цена решения 0001.

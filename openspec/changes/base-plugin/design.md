## Context

herdr владеет процессами агентов и даёт API сокета; Claude Code пишет
транскрипты, `meta.json` субагентов и файлы вывода фоновых команд. Плагин
собирает из этих двух источников единое дерево и работает с узлами из Neovim.
Форматы данных herdr и Claude Code описаны требованиями спецификаций
`herdr-client` и `claude-code-data`; здесь — сведения, которые не являются
поведением плагина.

- Форматы проверены на сервере herdr с протоколом 22 и Claude Code 2.1.x;
  форматы Claude Code не документированы и могут измениться.
- Схема API herdr — команда `herdr api schema --json`; описание для агентов —
  `herdr --skill`; снимок из командной строки — `herdr api snapshot`.
- Внутри панели herdr заданы `HERDR_WORKSPACE_ID`, `HERDR_TAB_ID`,
  `HERDR_PANE_ID`. Порядок выбора сокета самим herdr: ключ `--session`,
  переменная `HERDR_SOCKET_PATH`, переменная `HERDR_SESSION`, сокет по
  умолчанию; плагин берёт `HERDR_SOCKET_PATH`, без неё — сокет по умолчанию.
- История событий сервера не долговечна, снимок и события не имеют общей
  последовательности: события служат сигналом перечитать состояние.
- События хуков Claude Code `SubagentStart` и `SubagentStop` — запасной
  источник сведений о субагентах на случай изменения формата файлов; в
  базовый набор не входят.
- Подключение к терминалу агента — команда `herdr agent attach <цель>`
  (двоичный протокол, не JSON API).
- Устройство должно допускать наращивание возможностей: новые виды узлов и
  действия добавляются без переделки клиента и модели.

## Goals / Non-Goals

**Goals:**

- Дерево всех workspace, вкладок, панелей, субагентов и фоновых команд.
- Подключение к любому узлу, сообщения агентам, запуск сессий, история,
  вопросы по коду в темах.
- Всё обновляется по событиям.

**Non-Goals:**

- Запуск и владение процессами агентов (это herdr).
- Запись в субагентов и фоновые команды.
- Режим обучения, пакеты языков, выбор базы знаний (см. `proposal.md`).

## Decisions

Решения D1 и D7–D9 приняты пользователем; остальные приняты при подготовке
спецификаций и утверждаются пользователем вместе с дельтами.

### D1. Процессами агентов владеет сервер herdr

В условиях, когда агенты Claude Code уже работают в панелях herdr и herdr
предоставляет API сокета (снимок, события, чтение панелей, запуск и
приглашение агентов), учитывая, что порядок работы с агентами должен остаться
прежним, выбрано сделать плагин клиентом сокета API herdr, а процессами
агентов оставить во владении работающего сервера herdr, чтобы Neovim показывал
и направлял те же сессии, что видны в herdr, и не воспроизводил интерфейс
Claude Code, ценой зависимости от API форка herdr и невозможности
структурированно писать субагентам.

Отвергнуто: запуск `claude -p --input-format stream-json --output-format
stream-json` дочерними процессами Neovim для этих сессий — он заменял бы herdr
и требовал бы воспроизводить интерфейс Claude Code: разрешения, вопросы,
статусы и приглашение. Условие пересмотра: появление в Claude Code
документированного канала управления сессией и его перечня субагентов и
фоновых задач. Вопросы по коду (D7) этим решением не затронуты: они идут
отдельными сессиями, а не сессиями herdr.

### D2. Собственный интерфейс на API Neovim

Дерево, окна просмотра и окна ответов — собственные буферы и окна на API
Neovim, без обязательных зависимостей от сторонних плагинов. Выбор из списка
идёт через `vim.ui.select`, ввод строки — через `vim.ui.input`: их подменяют
плагины, установленные у пользователя. Отвергнута обязательная зависимость от
snacks.nvim или nui.nvim: она сужает круг пользователей публичного плагина.

### D3. Завершённые узлы остаются в дереве

Завершённые субагенты и фоновые команды остаются в дереве с состоянием
«завершён» до закрытия панели владельца. Показ завершённых узлов переключается
командой; состояние переключателя — настройка `show_finished` со значением по
умолчанию «показывать».

### D4. Подключение к контейнеру — перечень панелей

Подключение к workspace и к вкладке показывает перечень их панелей с
состояниями, из которого открывается вид панели. Автоматического выбора
«первой панели» нет.

### D5. Агенты других видов

Агенты не Claude Code показываются в дереве как панели с агентом, без
субагентов и фоновых команд: файлов таких агентов плагин не разбирает.

### D7. Вопросы по коду — отдельные сессии Claude Code

Тема вопросов по коду — отдельная сессия Claude Code, запущенная плагином как
процесс `claude -p` в каталоге проекта. Новый вопрос из буфера с кодом
открывает новую тему, вопрос из окна ответа продолжает тему этого окна
(`--resume <идентификатор>`); автоматического определения темы моделью нет.

Отвергнуто: отправка вопроса работающему агенту herdr как основной путь — она
вмешивается в его задачу, а агенту в состоянии `blocked` вопрос задать нельзя;
для сообщений агентам служит `messaging`. Отвергнуто как основной путь:
ответвление от заранее созданной «базовой сессии проекта» — оно окупается
только на небольшом проекте при частых вопросах, а по истечении часового срока
кэша запросов каждое ответвление оплачивает полный контекст базы; оставлено
необязательной настройкой, по умолчанию выключенной.

### D8. Реестр тем

Плагин хранит в каталоге состояния Neovim запись о каждой теме: идентификатор
сессии, каталог проекта, заголовок (начало первого вопроса), режим, файл и
символ, откуда задан вопрос, время создания и последнего обращения.
Содержимое темы берётся из транскрипта сессии, окно темы восстанавливается из
него. Возврат к теме — через перечень тем проекта и команду «последняя тема».
Тема, транскрипт которой удалён, остаётся в перечне с пометкой «содержимое
недоступно».

### D9. Точки расширения вопросов по коду

В изменении только точки расширения; режим обучения и пакеты языков — отдельные
изменения и отдельные плагины.

- Режим — именованный набор: наставление агенту (дополнение к системному
  запросу), модель, набор инструментов. Встроенный режим один — «вопрос по
  коду».
- Поставщик контекста — функция, которая по буферу и выделению возвращает
  пакет контекста. Встроенный общий поставщик даёт файл, строки, выделенный
  текст, охватывающий узел tree-sitter, определение и описание символа по
  стандартным запросам языкового сервера (если сервер подключён; его
  отсутствие не ошибка). Дополнительные поставщики регистрируются по типу
  файла и дополняют общий.
- Источник знаний — необязательный MCP-сервер, заданный настройкой для проекта
  и передаваемый отвечающему процессу; без него плагин работает.

### D10. Модель и инструменты вопросов по коду

Модель для вопросов по коду — настройка `model`, по умолчанию `sonnet`.
Отвечающий процесс получает только инструменты чтения, если режим не задаёт
иного.

### D11. Сообщения инстансам

Текст отправляется методом `agent.prompt`. Агенту в состоянии, в котором
`agent.prompt` отклоняется (ожидание ответа или разрешения), плагин предлагает
отправку клавиш (`pane.send_keys`) и показывает причину. Субагентам и фоновым
командам писать нельзя.

### D12. Проверки на живом сервере — на отдельном сервере

Проверки на живом сервере herdr при разработке ведутся на отдельном сервере,
не на рабочем.

### D13. Клиент сокета на Lua через `vim.uv`, без промежуточного демона

Плагин сам открывает Unix-сокет (`vim.uv.new_pipe`), разбирает строки JSON и
сопоставляет ответы запросам по `id`. Отдельного процесса-посредника нет:
состояние живёт в Neovim, второй источник правды не появляется. Подписка
держит отдельное соединение, остальные запросы идут другим.

### D14. События — сигналы перечитывания

События не накладываются на снимок: они помечают кэш устаревшим и запускают
перечитывание (`session.snapshot`, `pane.read`). Перечитывания сериализуются;
событие, пришедшее во время чтения, вызывает ещё одно.

### D15. Единый модуль разбора форматов Claude Code

Транскрипты, `meta.json`, записи вызовов фоновых команд и `task-notification`
разбирает один модуль (`claude-code-data`); остальной код получает от него
записи вида «субагент», «фоновая команда», «реплика диалога». Если формат
Claude Code изменится, правится один модуль.

### D16. Слежение за файлами без опроса

Каталог сессии, `subagents/`, транскрипты и файлы вывода отслеживаются
`vim.uv.new_fs_event`; дописываемые файлы читаются с запомненного смещения.

### D17. Модель дерева отдельно от отображения

Модель — узлы с видом, подписью, состоянием, родителем и действиями; она
строится из снимка herdr и записей модуля разбора и обновляется по событиям.
Отображение подписывается на изменения модели. Новая возможность добавляется
новым видом узла или действием, без правки клиента. Идентификатор узла
субагента или фоновой команды — `<панель владельца>/<идентификатор субагента
или задачи>`: у них нет идентификатора панели в API herdr.

### D18. Подключение к узлу зависит от вида узла

Панель с агентом — живой терминал (`herdr agent attach` в буфере терминала
Neovim); панель с командой — `pane.read` с обновлением по
`pane.output_changed`; субагент и фоновая команда — файлы Claude Code, только
чтение.

### D19. Запуск сессии

Новая вкладка — `tab.create` (ответ несёт `root_pane`), деление — `pane.split`;
затем `agent.start` с видом `claude` в созданной панели. Рабочий каталог
плагин не передаёт, действует значение по умолчанию herdr. `agent.start` ждёт
готовности агента на стороне сервера, Neovim остаётся отзывчивым: вызов
асинхронный.

## Risks / Trade-offs

- Форматы файлов Claude Code не документированы и могут измениться → единый
  модуль разбора, образцы транскриптов в тестах, запасной источник — хуки.
- Зависимость от API форка herdr (протокол 22) → проверка протокола при
  подключении, отказ с понятным сообщением.
- Невозможность структурированно писать субагентам → цена решения D1.
- Каждый вопрос по коду — отдельная сессия со своим расходом токенов → темы
  продолжаются из окна ответа, а не открываются заново.

## Open Questions

- Вид событий жизненного цикла (с точкой или с подчёркиванием) — проверяется.
- `herdr agent attach` для панели без агента — проверяется.
- Записи фоновых команд при ошибке и остановке — проверяется.
- Срок жизни файлов вывода фоновых команд — проверяется.
- Ключи `claude -p` и поток `stream-json` — проверяется.

## Context

Изменение добавляет к `base-plugin` ссылки на файлы, окно ввода сообщения и
диалоги агента без терминала. Ниже — проверенные факты о Claude Code и
herdr, которые не являются поведением плагина; поведение — в требованиях
`file-references`, `message-input`, `agent-dialogs`. Решения D1–D21 заданы в
`base-plugin` и здесь не пересматриваются.

**Стенд проверок.** herdr 0.9.5 (протокол 22), Claude Code 2.1.325, модель
`haiku`, отдельный тестовый сервер без терминала. Агент запускался с ключом
`--setting-sources project`: пользовательские настройки отключены, поэтому
`agent_session` у панели оставался пустым (поле заполняет хук
`SessionStart`), а транскрипт искался по самому свежему файлу каталога
проекта. Форматы Claude Code не документированы и могут измениться.

**Что отдаёт herdr.** Единственный признак диалога — `agent_status:
blocked` (в `agent get`, в снимке и событием `pane.agent_status_changed`),
приходит примерно через 0,2–0,35 с после показа диалога на экране. Полей с
вопросом, пунктами и видом диалога нет ни в `agent get`, ни в `pane.get`, ни
в снимке. Событие `pane.output_changed` несёт только `revision`.
`pane.read` сразу после `pane.send_keys` часто возвращает прежний экран.
`agent.prompt` в состоянии `blocked` отвечает `agent_blocked`; при `working`
принимается и встаёт в очередь (в транскрипте `queue-operation`
`enqueue`/`dequeue`, затем запись `user` после конца хода).

**Порядок событий при вопросе (одна серия, с хуками).** `PreToolUse` →
`PermissionRequest` (через 32 мс) → кадр с диалогом (+11 мс) → запись
`assistant` с `tool_use` в транскрипте (+64 мс) → `blocked` (+181 мс).
`Notification` приходит через 6–10 с и содержимого диалога не несёт.

**Транскрипт до ответа.** Запись `tool_use` для запроса разрешения Bash есть
до ответа и без хуков. Для вопроса и плана запись до ответа наблюдалась
только в сессиях с хуками; в двух сессиях без хуков за 20 с её не было.
Поэтому транскрипт не может быть источником содержимого диалога.

**Входы хуков.** `PreToolUse` несёт `tool_name`, `tool_input` (для
`AskUserQuestion` — `questions[]` целиком: `question`, `header`,
`multiSelect`, `options[].label/description`; для `ExitPlanMode` — `plan`,
`planFilePath`), `tool_use_id`, `cwd`, `permission_mode`. `PermissionRequest`
несёт `tool_name`, `tool_input` (для Bash — `command`, `description`; для
Write — `file_path`, `content`), `permission_suggestions` (Bash, Write) и в
образцах не несёт `tool_use_id`. Образцы обезличены, поэтому наличие
`session_id` и пути транскрипта во входе хука на стенде не зафиксировано.

**Ответ клавишами** (`pane.send_keys` с `keys`, `pane.send_text` с `text`):

| Диалог | Последовательность |
|---|---|
| вопрос, один выбор | цифра пункта подтверждает сразу, Enter не нужен |
| вопрос, свой ответ | `Down` до пункта «Type something» (по числу пунктов), `send_text`, `Enter`; `\n` в тексте — новая строка поля, не отправка |
| multiSelect | цифра переключает отметку, выделение не двигается; от первого пункта `Down` на число пунктов плюс один — «Next» (строка без номера); `Enter` |
| несколько вопросов | `Enter` на «Next» ведёт к следующему вопросу; цифра в одиночном вопросе последней карточки ведёт на вкладку «Review your answers» (без подвала); `Enter` на «1. Submit answers» отправляет |
| разрешение | цифра подтверждает пункт сразу: `1` — «Yes»; `Escape` — отказ; число пунктов зависит от инструмента (Bash — четыре, Write — три) |
| план | цифра `2` подтвердила сразу; подвал диалога без «Enter to select» и «Esc to cancel» |
| отмена | `Escape` отменяет весь вопрос с первого нажатия |

Цифры, посланные, пока выделено поле «Type something», вводятся в поле как
текст. Кавычки, `!`, `/`, кириллица в тексте ответа доходят.

**Закрытие диалога.** Ответ — запись `user` с `tool_result` для вызова
(`toolUseResult.answers` у вопроса; «User has approved your plan» у плана).
Отмена и отказ — `tool_result` с `is_error` и «The user doesn't want to
proceed…», затем запись `user` «[Request interrupted by user for tool use]»,
`PostToolUse` нет, состояние → `idle`. После ответа состояние идёт
`blocked` → `working` напрямую.

**Сообщение агенту.** Многострочный текст доходит одним сообщением: herdr
отправляет его вставкой (bracketed paste), в транскрипте запись обёрнута в
`<pasted_content id=…>`; порог обёртки не выяснялся. Начало с `/` Claude Code
разбирает как команду, с `!` — переводит поле в режим оболочки; начало с
пробела перед `/` — обычное сообщение, пробел остаётся в тексте.

**Не проверено.** Пункты «Tell Claude what to change» и Escape в диалоге
плана; одиночный вопрос с `multiSelect` (последняя позиция вместо «Next»);
цифра в одиночном вопросе не последней карточки; пункт «Type something» у
вопроса с `multiSelect`; Escape в поле свободного ввода в vim-режиме Claude
Code; пробел перед `!`; запись `tool_use` для `ExitPlanMode` без хуков;
наличие `session_id` во входе хука; диалоги субагентов, доверия каталогу и
серверов MCP.

## Goals / Non-Goals

**Goals:**

- Путь под курсором в любом буфере с содержимым Claude Code открывается
  предпросмотром и переходом.
- Сообщение агенту набирается как обычный текст в Neovim.
- Диалоги агента отрабатываются из Neovim без терминала, когда содержимое
  диалога известно от хука; иначе остаётся терминал.

**Non-Goals:**

- Разбор экрана панели; пункты диалога, неизвестные без экрана.
- Диалоги, которых нет в наблюдениях; диалоги субагентов.
- Хранение черновиков между запусками Neovim.

## Decisions

Решения D22, D23, D32, D33 и часть D24, D27, D30 приняты пользователем;
остальные приняты при подготовке спецификаций и утверждаются пользователем
вместе с дельтами. Нумерация продолжает `base-plugin`.

### D22. Содержимое диалога — от хука Claude Code

В условиях, когда herdr отдаёт только состояние `blocked`, а транскрипт не
гарантирует запись вопроса и плана до ответа, учитывая, что хуки
`PreToolUse` и `PermissionRequest` получают `tool_input` до показа диалога,
выбрано брать структуру диалога от хука, поставляемого с плагином, и писать
её файлом в каталог обмена, чтобы буфер диалога строился из разобранных
данных и не зависел от внешнего вида экрана, ценой установки хука в Claude
Code (сессия без хука остаётся на терминале). Принято пользователем.

### D23. Разбор экрана не делается

В условиях, когда подвал, нумерация и строки вкладок меняются между
диалогами (у плана нет подвала «Enter to select»), выбрано не разбирать экран
панели ни в каком случае и при отсутствии структуры предлагать терминал,
чтобы изменение оформления Claude Code не ломало плагин незаметно, ценой
отказа от диалогов без хука. Принято пользователем.

### D24. Хук поставляется плагином Claude Code

В условиях, когда хук должен быть установлен у пользователя, а ставить его
вручную в настройки неудобно, выбрано поставлять плагин Claude Code в
каталоге `claude-plugin/` репозитория (манифест, описание хуков, сценарий) и
описать установку в `docs/`, чтобы хук обновлялся вместе с плагином. Принято
пользователем в части поставки; состав событий и сценарий — на утверждение с
дельтой: `PreToolUse` для `AskUserQuestion` и `ExitPlanMode` (несёт
`tool_use_id`, нужный для сопоставления с результатом) и `PermissionRequest`
для остальных инструментов; запись `PermissionRequest` для двух первых
пропускается, чтобы не терять `tool_use_id`. Сценарий — Lua-файл, который
запускает `nvim --clean -l`: Neovim у пользователя уже есть, `jq` и
оболочка не нужны. Отвергнуто: `jq` с оболочкой — лишняя зависимость.

### D25. Каталог обмена и файл диалога

В условиях, когда хук запускает Claude Code, а читает файл Neovim, выбрано
положить файл в `claudr/dialogs` каталога состояния пользователя
(`XDG_STATE_HOME`, иначе `~/.local/state`; каталог состояния самого Neovim не
подходит: хук его не знает), назвать `<идентификатор сессии>.json` и писать
атомарно (временный файл и переименование), чтобы уведомление файловой
системы приходило о готовом файле, ценой того, что у сессии один открытый
диалог: новый заменяет прежний. Формат: JSON, поля `version`, `session_id`,
`pane_id`, `hook_event`, `tool_name`, `tool_use_id`, `tool_input`,
`permission_suggestions`, `cwd`; `tool_input` сохраняется как есть, разбирает
его модуль `claude-code-data` (D15). Идентификатор панели хук берёт из
`HERDR_PANE_ID` окружения Claude Code: он запасной ключ привязки, если во
входе хука нет `session_id` (не проверено). Каталог заменяется переменной
окружения для тестов и нестандартных установок. На утверждение с дельтой.

Имя «по идентификатору сессии и вызова инструмента» не выбрано:
`PermissionRequest` не несёт `tool_use_id`, а у сессии не бывает двух
открытых диалогов. Для запроса разрешения вызов определяется по транскрипту
(последний вызов того же инструмента без результата), где запись есть до
ответа.

### D26. Файл убирает плагин

В условиях, когда `PostToolUse` не приходит при отказе и отмене, а хук не
знает о закрытии диалога, выбрано удалять файл силами плагина после
закрытия диалога и при запуске (вызов имеет результат либо сессия не
принадлежит ни одной панели), чтобы каталог не копил устаревшие файлы, ценой
файлов, оставшихся без работающего Neovim (их убирает следующий запуск или
следующая запись той же сессии). Файл не удаляется только из-за состояния
не `blocked`: состояние запаздывает относительно записи. На утверждение с
дельтой. Отвергнуто: удаление хуком — он не видит закрытия.

### D27. Закрытие диалога

В условиях, когда ответ может быть дан из другого клиента или в самой
панели, выбрано считать диалог закрытым по результату вызова в транскрипте
(`tool_result` для вызова) либо по выходу панели из `blocked`, чтобы буфер
диалога закрывался или помечался отвеченным при любом источнике ответа,
ценой второго признака (выход из `blocked`), который не требует чтения
файлов. Принято пользователем в части транскрипта; второй признак — на
утверждение с дельтой.

### D28. Ответ клавишами по таблице

В условиях, когда формы ответа различаются по видам диалога, а
последовательности зависят от версии Claude Code, выбрано собрать их в одну
таблицу в одном модуле и строить ответ только из подтверждённых наблюдениями
последовательностей (цифра для одиночного выбора и разрешения; стрелки,
`send_text`, `Enter` для свободного ввода; цифры, `Down`, `Enter` для
множественного выбора; накопление ответов и отправка всех клавиш подряд на
итоговой вкладке), чтобы расхождение с новой версией исправлялось в одном
месте, ценой отказа от непроверенных пунктов. На утверждение с дельтой;
последовательности — по наблюдениям, непроверенное отмечено в Context и
проверяется живой проверкой (этап 6 `tasks.md`).

### D29. Разрешение — только «разрешить один раз» и «отказать»

В условиях, когда число и порядок пунктов диалога разрешения зависят от
инструмента и режима и известны только по экрану, выбрано предлагать два
действия (`1`, `Escape`) и оставлять остальные пункты терминалу, чтобы не
разбирать экран, ценой отсутствия «всегда разрешать» в буфере. Тот же
подход к плану: действия `1` и `2` по наблюдению, пункт «Tell Claude what to
change» не предлагается. Пункт «Chat about this» не показывается нигде. На
утверждение с дельтой.

### D30. Окно ввода сообщения общее для сообщений и свободного ввода

В условиях, когда сообщение агенту и свободный ответ на вопрос — один и тот
же набор текста, выбрано использовать одно всплывающее окно с обычным
редактированием, отправкой сохранением (`:w`), Shift+Enter или Shift+Space и
разной целью отправки (`agent.prompt` либо ответ диалога), чтобы не
плодить интерфейсы. Принято пользователем. Черновик (закрытие без отправки
сохраняет текст до следующего открытия для той же сессии; в памяти Neovim) —
на утверждение с дельтой. Shift+Enter и Shift+Space различимы только
терминалом с расширенным протоколом клавиатуры; `:w` работает всегда.

### D31. Начало сообщения с `/` или `!`

В условиях, когда пользователь мог написать команду Claude Code намеренно, а
вставляемый текст может начинаться с `/` или `!` случайно, выбрано
отправлять текст как есть и сообщать об этом перед отправкой, предоставив
настройку защиты ведущим пробелом, чтобы не лишать пользователя команд,
ценой возможной случайной команды. На утверждение с дельтой. Вариант:
защита по умолчанию включена — безопаснее для вставки, но команды тогда
набираются с обходом. Пробел перед `!` не проверен.

### D32. Ссылки на файлы — общий разбор и клавиши только в буферах плагина

В условиях, когда содержимое Claude Code показывают шесть видов буферов,
выбрано определять ссылку одним модулем (виды `файл`, `файл:строка`,
`файл:строка:столбец`; относительный путь — от рабочего каталога сессии
владельца буфера: `cwd` панели, для субагента и фоновой команды — `cwd`
панели владельца, для диалога из истории — каталог проекта сессии, для темы
— каталог проекта темы; несуществующий путь и каталог ссылкой не считаются)
и назначать `K` (предпросмотр на строке в плавающем окне, только чтение,
фокус на месте, закрытие по движению курсора и Escape) и `gd` (открытие в
окне редактирования на строке и столбце) только в этих буферах, чтобы
остальные буферы не затрагивались, ценой переназначения настройкой. Вне
ссылки клавиши работают как обычно. Принято пользователем.

### D33. Без самовольной смены окна

В условиях, когда агент переходит в ожидание, пока пользователь работает в
другом окне, выбрано только сообщать об этом и о команде открытия диалога,
не меняя окно и фокус. Принято пользователем.

## Что уточняет base-plugin

Изменение не оформляет правки как MODIFIED: `base-plugin` не архивировано,
основных спецификаций нет. Уточняются требования (приводятся к новому виду
задачей 7.2 `tasks.md` после архивации `base-plugin`):

- `code-questions`, «Ссылки на код в ответе» — клавиши и предпросмотр задаёт
  `file-references`; переход там соответствует `gd`.
- `messaging`, «Агент в состоянии без приёма сообщений» — вместо предложения
  клавиш открывается буфер диалога, если структура диалога известна;
  предложение терминала остаётся для остальных случаев. Решение D11
  уточняется так же.
- `node-view`, «Панель — ввод отдельной командой» — остаётся запасным путём
  для сессий без хука и нераспознанных диалогов.
- `messaging`, «Сообщение агенту» — ввод текста идёт окном `message-input`,
  а не `vim.ui.input` (D2 для остальных запросов не меняется).

## Risks / Trade-offs

- Последовательности клавиш зависят от версии Claude Code → таблица в одном
  модуле, живая проверка непроверенных пунктов до включения (этап 6),
  сверка результата вызова с выбранным после закрытия.
- Диалог не закрылся после ответа (клавиши не подошли): признака неуспеха по
  событию нет — см. Open Questions; плагин показывает состояние ожидания
  закрытия и всегда предлагает терминал.
- Хук не установлен или не сработал → диалог остаётся на терминале
  (требование «Диалог без структуры»).
- Файл диалога записан, а диалога нет (например, `ExitPlanMode` вне режима
  плана или при автоматическом разрешении) → диалог открывается только в
  состоянии `blocked`, файл закрывается по результату вызова.
- Привязка по `session_id` зависит от его наличия во входе хука (не
  проверено) → запасная привязка по `pane_id` из окружения.
- Запоздание состояния относительно файла → файл не удаляется по одному
  состоянию, диалог открывается только в `blocked`.

## Open Questions

1. Признак неуспеха ответа без таймера. После отправки клавиш у сервера нет
   события «клавиши не подошли»: если диалог не закрылся, не приходит ни
   события herdr, ни записи транскрипта. Варианты:
   - (рекомендуется) только показывать состояние «ожидается закрытие» и
     предлагать терминал, ничего не выдумывая: расхождение видно по
     результату вызова, когда диалог закрылся иначе;
   - использовать `pane.output_changed` после отправки как признак, что
     экран изменился, а состояние осталось `blocked` — признак двусмыслен
     (так же ведёт себя переход к следующему вопросу);
   - ввести срок ожидания (таймер) — запрещено без решения пользователя.
2. Непроверенные последовательности (Context, «Не проверено»), если живая
   проверка не подтвердит. Варианты: (рекомендуется) включать в буфер только
   подтверждённые виды, остальные оставлять терминалу; ограничить диалоги
   видами «вопрос с одним выбором» и «разрешение».

## ADDED Requirements

### Requirement: Плагин Claude Code с хуком
Вместе с claudr.nvim MUST поставляться плагин Claude Code (каталог `claude-plugin/`), который вешает хук на `PreToolUse` для `AskUserQuestion` и `ExitPlanMode` и на `PermissionRequest` для остальных инструментов и записывает по вызову файл диалога. Запись по `PermissionRequest` для `AskUserQuestion` и `ExitPlanMode` MUST пропускаться: их пишет `PreToolUse`, который несёт `tool_use_id`.

#### Scenario: Вопрос
- **WHEN** хуку приходит вход `PreToolUse` с `tool_name` `AskUserQuestion`
- **THEN** хук пишет файл диалога, а последующий вход `PermissionRequest` с тем же инструментом файла не меняет

#### Scenario: Разрешение инструмента
- **WHEN** хуку приходит вход `PermissionRequest` с `tool_name` `Bash`
- **THEN** хук пишет файл диалога с командой из `tool_input`

### Requirement: Хук не меняет поведение Claude Code
Хук MUST завершаться кодом 0, MUST NOT печатать решение или другой вывод и MUST NOT писать ничего, кроме файла диалога. Запись MUST быть атомарной: файл создаётся под временным именем и переименовывается. Ошибка хука (нет каталога, нет прав) MUST NOT мешать показу диалога.

#### Scenario: Обычный вызов
- **WHEN** хук получает вход
- **THEN** процесс завершается с кодом 0, stdout пуст, в каталоге обмена появился только файл диалога

#### Scenario: Каталог недоступен
- **WHEN** запись файла не удаётся
- **THEN** хук завершается с кодом 0 без вывода, диалог Claude Code показывается как обычно

### Requirement: Каталог обмена и файл диалога
Файл диалога MUST лежать в каталоге `claudr/dialogs` каталога состояния пользователя (`XDG_STATE_HOME`, без неё `~/.local/state`); плагин и хук MUST позволять заменить каталог переменной окружения. Имя — `<идентификатор сессии>.json`: у сессии не больше одного открытого диалога, новая запись заменяет прежнюю. Поля: `version`, `session_id`, `pane_id` (из `HERDR_PANE_ID`, если задана), `hook_event`, `tool_name`, `tool_use_id` (если есть), `tool_input`, `permission_suggestions` (если есть), `cwd`.

#### Scenario: Заменяющая запись
- **WHEN** сессия получает второй диалог до удаления файла первого
- **THEN** файл `<идентификатор сессии>.json` содержит данные второго диалога

#### Scenario: Нестандартный каталог
- **WHEN** задана переменная окружения с каталогом обмена
- **THEN** хук пишет, а плагин читает файлы в этом каталоге

### Requirement: Обнаружение файла без опроса
Плагин MUST узнавать о файлах диалога уведомлением файловой системы (`vim.uv.new_fs_event`) на каталог обмена; при запуске MUST однократно прочитать уже лежащие файлы. Временные файлы записи MUST игнорироваться. Каталог обмена, которого нет, MUST создаваться плагином.

#### Scenario: Новый файл
- **WHEN** хук создаёт файл диалога
- **THEN** плагин получает уведомление и читает файл без действий пользователя

#### Scenario: Временный файл
- **WHEN** в каталоге появляется временный файл записи
- **THEN** плагин его не читает до переименования

### Requirement: Разбор в модуле claude-code-data
Файл диалога MUST разбираться тем же модулем, что транскрипты (`claude-code-data`). Модуль MUST возвращать запись вида «диалог»: вид (`question` для `AskUserQuestion`, `plan` для `ExitPlanMode`, иначе `permission`), вопросы с пунктами и признаком `multiSelect`, текст плана, команда или файл и содержимое для разрешения. Неизвестные поля и инструменты MUST NOT вызывать ошибку.

#### Scenario: Вопрос с вариантами
- **WHEN** файл содержит `AskUserQuestion` с одним вопросом и тремя пунктами
- **THEN** модуль возвращает диалог вида `question` с тремя пунктами и подписями

#### Scenario: Неизвестный инструмент
- **WHEN** в файле `tool_name` — инструмент, которого плагин не знает
- **THEN** диалог вида `permission` с исходным `tool_input`, ошибки нет

### Requirement: Привязка диалога к панели
Диалог MUST привязываться к панели, у которой `agent_session.value` равно `session_id` файла; если совпадения нет, — к панели с `pane_id` из файла. Диалог без панели MUST NOT показываться.

#### Scenario: Совпадение сессии
- **WHEN** у панели `agent_session.value` равно `session_id` файла
- **THEN** диалог привязан к этой панели

#### Scenario: Сессия неизвестна серверу
- **WHEN** ни у одной панели нет такого `agent_session.value`, а `pane_id` файла совпадает с панелью
- **THEN** диалог привязан к панели по `pane_id`

### Requirement: Открытый диалог
Диалог MUST считаться открытым, когда у панели состояние `blocked`, и MUST оставаться таким, пока у вызова нет результата в транскрипте и состояние не изменилось. Вызов — `tool_use_id` файла, а без него последний вызов того же инструмента без результата. Файл без `blocked` MUST NOT открывать диалог.

#### Scenario: Диалог появился
- **WHEN** файл диалога прочитан, затем приходит `pane.agent_status_changed` с `blocked`
- **THEN** диалог открыт

#### Scenario: Файл без ожидания
- **WHEN** файл есть, а состояние панели `working`
- **THEN** диалог не открыт

### Requirement: Закрытие диалога
Диалог MUST закрываться, когда в транскрипте появляется результат вызова (`tool_result` для `tool_use_id`, в том числе с ошибкой) либо состояние панели выходит из `blocked`. Буфер диалога MUST закрываться или помечаться отвеченным, в том числе когда ответ дан из другого клиента. Файл диалога MUST удаляться плагином после закрытия.

#### Scenario: Ответ из другого клиента
- **WHEN** диалог открыт, пользователь отвечает в терминале панели, в транскрипте появляется `tool_result`
- **THEN** буфер диалога помечен отвеченным или закрыт, файл диалога удалён

#### Scenario: Выход из blocked
- **WHEN** состояние панели меняется с `blocked` на `working`
- **THEN** диалог закрыт

### Requirement: Очистка устаревших файлов
При запуске плагин MUST удалять файлы диалогов, у которых вызов уже имеет результат в транскрипте или сессия не принадлежит ни одной панели. Файл MUST NOT удаляться только из-за того, что состояние панели не `blocked`: оно запаздывает относительно записи файла.

#### Scenario: Диалог закрыт без плагина
- **WHEN** при запуске есть файл, а в транскрипте у вызова есть результат
- **THEN** файл удалён

#### Scenario: Запись раньше состояния
- **WHEN** файл прочитан до прихода `blocked`
- **THEN** файл остаётся до закрытия диалога

### Requirement: Буфер диалога
Диалог MUST показываться обычным буфером только для чтения с навигацией Vim, курсор на первом пункте. Вопрос показывает текст вопроса, пункты с описаниями и подписями вида; разрешение — инструмент и содержимое (команда, либо файл и текст); план — текст плана. Буфер MUST открываться одной командой из узла дерева и из вида панели.

#### Scenario: Вопрос из узла дерева
- **WHEN** пользователь вызывает команду диалога на узле панели с открытым вопросом
- **THEN** открывается буфер только для чтения с вопросом и пунктами, курсор на первом пункте

#### Scenario: Диалога нет
- **WHEN** команда вызвана на узле без открытого диалога
- **THEN** плагин сообщает, что открытого диалога нет

### Requirement: Сообщение об ожидании ответа
Когда у панели с открытым видом агент переходит в `blocked`, плагин MUST сообщить об ожидании ответа и, если структура диалога есть, о команде открытия буфера диалога; окно и фокус MUST NOT меняться. Если структуры нет, сообщение предлагает подключение с вводом через терминал.

#### Scenario: Структура есть
- **WHEN** вид панели открыт, агент переходит в `blocked`, файл диалога прочитан
- **THEN** плагин сообщает о диалоге и команде открытия, окно и фокус прежние

#### Scenario: Структуры нет
- **WHEN** агент переходит в `blocked`, файла диалога нет
- **THEN** плагин сообщает, что агент ждёт ответа, и предлагает подключение с вводом

### Requirement: Одиночный выбор
Enter на пункте вопроса с одним выбором MUST отправлять в панель цифру пункта через `pane.send_keys` (Claude Code подтверждает пункт сразу, Enter не нужен). Для каждого вида диалога последовательности MUST быть заданы таблицей в одном модуле.

#### Scenario: Выбор второго пункта
- **WHEN** пользователь нажимает Enter на втором пункте вопроса с тремя пунктами
- **THEN** сервер получает `pane.send_keys` с целью этой панели и клавишей `2`

### Requirement: Свободный ввод
Пункт «свой ответ» (после перечня пунктов вопроса с одним выбором) MUST открывать окно ввода сообщения (`message-input`) с той же отправкой. Ответ MUST уходить тремя шагами: `pane.send_keys` со стрелками `Down` до пункта (по числу пунктов вопроса), `pane.send_text` с текстом, `pane.send_keys` с `Enter`.

#### Scenario: Свой ответ на вопрос с тремя пунктами
- **WHEN** пользователь выбирает пункт свободного ввода и отправляет текст из двух строк
- **THEN** сервер получает `Down` трижды, затем `pane.send_text` с текстом из двух строк, затем `Enter`

### Requirement: Множественный выбор
Для вопроса с `multiSelect` Enter на пункте MUST переключать отметку пункта в буфере, ничего не отправляя; отдельная команда подтверждения MUST отправлять отмеченные пункты: цифры отметок, затем `Down` до пункта «Next» (по числу пунктов вопроса плюс один) и `Enter`.

#### Scenario: Две отметки
- **WHEN** в вопросе с тремя пунктами отмечены первый и третий, пользователь подтверждает
- **THEN** сервер получает клавиши `1`, `3`, затем `Down` четырежды, затем `Enter`

#### Scenario: Снятие отметки
- **WHEN** пользователь нажимает Enter на отмеченном пункте
- **THEN** отметка снята, в панель ничего не отправлено

### Requirement: Несколько вопросов
Вопросы одного вызова MUST показываться по очереди; ответы MUST накапливаться в плагине, итоговый экран MUST показывать все ответы и ждать подтверждения. Подтверждение MUST отправлять клавиши всех вопросов подряд и клавишу `Enter` на пункте отправки итоговой вкладки Claude Code.

#### Scenario: Два вопроса
- **WHEN** пользователь ответил на оба вопроса и подтвердил итоговый экран
- **THEN** сервер получает последовательность клавиш обоих ответов и завершающий `Enter`

#### Scenario: Возврат к вопросу
- **WHEN** на итоговом экране пользователь возвращается к первому вопросу
- **THEN** ответы сохранены, клавиши в панель не отправлены

### Requirement: Разрешение на инструмент
Буфер разрешения MUST давать два действия: разрешить один раз (клавиша `1`) и отказать (`Escape`). Остальные пункты Claude Code («всегда разрешать» и подобные) MUST NOT предлагаться: их число и порядок без экрана неизвестны; для них остаётся терминал.

#### Scenario: Разрешить
- **WHEN** пользователь выбирает «разрешить один раз» в диалоге Bash
- **THEN** сервер получает `pane.send_keys` с клавишей `1`

#### Scenario: Отказать
- **WHEN** пользователь выбирает «отказать»
- **THEN** сервер получает `pane.send_keys` с клавишей `Escape`

### Requirement: Подтверждение плана
Буфер плана MUST показывать текст плана и два действия: первый и второй пункт диалога Claude Code (клавиши `1` и `2`) с подписями из таблицы клавиш (в проверенной версии: «Yes, and use auto mode», «Yes, manually approve edits»). Пункт «Tell Claude what to change» MUST NOT предлагаться, пока его последовательность не проверена.

#### Scenario: Второй пункт
- **WHEN** пользователь выбирает действие второго пункта в буфере плана
- **THEN** сервер получает `pane.send_keys` с клавишей `2`

### Requirement: Отмена диалога
Отдельная клавиша буфера MUST отправлять в панель `Escape` без запроса подтверждения намерения. Из состояния свободного ввода отмена MUST работать так же, как из любого другого пункта.

#### Scenario: Отмена вопроса
- **WHEN** пользователь нажимает клавишу отмены в буфере вопроса
- **THEN** сервер получает `pane.send_keys` с `Escape`, подтверждения плагин не спрашивает

### Requirement: Состояние после ответа
После отправки ответа буфер MUST показывать состояние «ответ отправлен, ожидается закрытие диалога» и MUST NOT повторять отправку. Когда диалог закрывается, плагин MUST сверить результат вызова из транскрипта с выбранным: если ответ принят иначе (ответ вопроса отличается от выбранного, отказ при выборе разрешения), пользователю MUST показываться расхождение с предложением подключения с вводом.

#### Scenario: Ответ принят
- **WHEN** после выбора `Blue` в транскрипте появляется `tool_result` с ответом `Blue`
- **THEN** буфер помечен отвеченным, расхождения нет

#### Scenario: Расхождение
- **WHEN** выбрано `Blue`, а `tool_result` содержит ответ `Green`
- **THEN** плагин показывает расхождение и предлагает подключение с вводом

#### Scenario: Диалог не закрылся
- **WHEN** ответ отправлен, а результата вызова нет и состояние `blocked`
- **THEN** буфер остаётся в состоянии ожидания закрытия, плагин не повторяет отправку и не ставит срок

### Requirement: Диалог без структуры или нераспознанный
Для сессии без хука и для диалога, который не распознан (доверие каталогу, серверы MCP, неизвестный вид), плагин MUST сообщать, что агент ждёт ответа, и предлагать подключение с вводом через терминальный буфер (`node-view`). Плагин MUST NOT разбирать экран панели.

#### Scenario: Сессия без хука
- **WHEN** агент в `blocked`, файла диалога у сессии нет
- **THEN** плагин сообщает об ожидании и предлагает подключение с вводом, чтения экрана (`pane.read`) нет

### Requirement: Отсутствие таймеров и опроса
Обнаружение файлов, открытие и закрытие диалога, ожидание закрытия после ответа MUST идти по событиям: уведомления файловой системы, события herdr, дописывание транскрипта. Таймеры и опрос MUST NOT использоваться.

#### Scenario: Тишина
- **WHEN** диалог открыт, ответа нет, событий нет
- **THEN** плагин не читает ни сокет, ни файлы

## Context

Решение D62 (изменение tree-tabs-only, архив) считает работающим вызовом любой обычный файл
`.output` каталога задач, не принадлежащий фоновой команде. На рабочей машине такие файлы
остаются от прерванных вызовов: Claude Code не удаляет их, а записи с идентификатором задачи
в транскрипте нет. Узлы этих файлов висят в дереве без команды.

## Decisions

### D66. Работающий вызов — файл с живым процессом

В условиях, когда пользователь выбрал показывать работающим вызовом только файл, в который
пишет живой процесс, учитывая, что libuv не даёт события о завершении чужого процесса, а
опрос запрещён, выбрано: при появлении файла и по следующим уведомлениям о нём (не больше
трёх попыток) модуль данных ищет в `/proc` процесс оболочки вызова — процесс с `eval '…'` в
командной строке, у которого поток вывода направлен в файл; найденный номер процесса
запоминается. Работающий вызов отдаётся, только пока процесс жив: при каждом пересчёте
состояния сессии (уведомление каталога задач о появлении или удалении файла, дописывание
транскрипта сессии или субагента; дописывание самого файла вывода пересчёта не вызывает) проверяется, что `/proc/<pid>/fd/1` указывает
на тот же файл. Процесс исчез — запись снимается и для этого файла больше не ищется. Узел
прерванного вызова исчезает по событию, которое приходит при прерывании: Claude Code
дописывает в транскрипт вызов и его результат с `interrupted`. Так в дереве нет висящих
узлов, без опроса, ценой: без `/proc` (не Linux, сервер herdr на другой машине) работающие
вызовы не показываются; если до завершения процесса не пришло ни одного события, узел
держится до следующего события сессии.

Отвергнуто: файлы старше начала сессии не показывать — признак косвенный, старый файл живого
вызова скрылся бы; оставить как есть — висящие узлы.

## Risks / Trade-offs

- Номер процесса может достаться другому процессу; проверка направления потока вывода в тот
  же файл это исключает.

## Context

Пользователь проверил дерево на живой панели и сказал дословно: «Shift-K не работает. По
enter лучше открывать не плавающее окно, а буфер в том окне, из которого открылось дерево.
При gd новый буфер с файлом, на который был переход, открывать в том же окне, из которого
был переход.» Требование сформулировано пользователем, поэтому код и тесты написаны в этом
же изменении; дельты спецификаций показываются пользователю до архивации.

Прочитано: `openspec/specs/node-view`, `file-references`, `agent-tree`; решения D18, D20
(`base-plugin`), D32 (`interactive-buffers`); `docs/node-view.md`, `docs/file-references.md`,
`docs/tree.md`.

**Приоритеты при выборе** (порядок предпочтений): слова пользователя; привычное поведение
Neovim (окно, из которого пришли, список переходов `<C-o>`, альтернативный буфер); без
таймеров, `sleep` и опроса; меньше правок вне видов, ссылок, дерева (только место открытия
вида), тестов и документов; публичность репозитория.

**Причина неработающего Shift+K** (исправлена отдельным коммитом, без дельты: поведение
возвращено к спецификации). Claude Code ставит неразрывный пробел (U+00A0) после знаков `⎿` и
`●`; в буфере терминала вида он стоит прямо перед путём. Разбор ссылки (`claudr.refs.parse`)
считал границами только ASCII-пробелы, поэтому неразрывный пробел входил в путь, файл не
находился (`resolve` принимал путь за относительный), и `K` выполнял обычное действие
(`keywordprg`) вместо предпросмотра. Воспроизведено на строке `  ⎿ \u{a0}/абсолютный/путь:12`;
тест `tests/refs/parse_spec.lua` и сквозной тест `tests/view/window_spec.lua`. Другие
проверенные причины не подтвердились: привязка `K` стоит на буфере вида и перед `ru-layout`,
which-key и noice не перехватывает (в Neovim с конфигурацией пользователя, в псевдотерминале
и в Neovide предпросмотр на ссылке открывался), щелчок мышью в терминале режим терминала не
включает, разбор путей из реального вывода панелей даёт ссылку.

## Decisions

### D50. Вид узла — обычный буфер в окне, плавающее окно для видов отменяется

В условиях, когда плавающий вид закрывает окна пользователя, не вписывается в список
переходов и альтернативный буфер, учитывая слова пользователя («буфер в том окне, из
которого открылось дерево»), выбрано открывать виды узлов (наблюдение, подключение с вводом,
история панели, транскрипт субагента, вывод команды, перечень панелей) обычным буфером в
окне, чтобы с ними работали `<C-o>`, `:ls`-переходы и привычные команды окон, ценой того, что
вид занимает окно пользователя, а не всплывает над ним. Заменяет форму «плавающее окно» видов
(`docs/node-view.md`, D18/D20 меняют только форму окна, не содержание вида).

### D51. Выбор окна для вида

В условиях, когда вид открывается из дерева, из другого вида или командой `:Claudr view`,
выбрано брать окно по порядку: текущее обычное окно, если оно не окно дерева (команда и
действия видов); окно, из которого открыто дерево (запоминается при каждом вызове
`:Claudr tree` из обычного окна); предыдущее окно; любое другое обычное окно вкладки; иначе
новое окно справа от дерева (`rightbelow vertical new`), чтобы вид оказался там, где пользователь
ждёт, и дерево осталось на месте, ценой того, что команда `:Claudr view`, вызванная в окне с
файлом, заменяет его буфер на вид (файл остаётся в списке переходов). Окно с `winfixbuf` не
берётся. Для `i` (подключение с вводом) и `S` (история) выбрано то же правило, что для `<CR>`:
единообразие. Перечень панелей и вид выбранной панели открываются в одном окне; `<C-o>`
возвращает к перечню.

### D52. Буфер вида переживает уход из окна

В условиях, когда `gd` и другие переходы уводят окно из буфера вида, а `<C-o>` должен
возвращать в него, выбрано держать буфер вида скрытым (`bufhidden = hide`, не в списке
буферов), а освобождать вид (наблюдение, подписки) только при удалении буфера и при закрытии
окна, где вид показан, если буфер нигде больше не виден, чтобы возврат не терял наблюдение,
ценой того, что скрытый вид продолжает получать кадры, пока не закрыт. Окно ищется по
событиям (`WinClosed`, `BufWipeout`), таймеров нет.

### D53. `q` оставляет окно

В условиях, когда окно с видом — окно пользователя, выбрано при закрытии вида (`q`, ошибка
подключения, конец подключения с вводом) показывать в окне альтернативный буфер, иначе пустой,
а буфер вида удалять, чтобы раскладка окон не менялась, ценой пустого буфера в окне, когда
прежнего нет. Удаление буфера командой пользователя (`:bwipeout`) закрывает окна по правилам
редактора и здесь не перехватывается. Буфер диалога из истории получил то же поведение
(`bufhidden = hide`, закрытие окна и `q` удаляют буфер), иначе `gd` из него терял бы диалог.

### D54. `gd` — в том же окне, заменяет часть D32

В условиях, когда пользователь просит открывать файл в окне, из которого сделан переход,
выбрано открывать его обычным `:edit` в текущем окне после `m'` (запись в список переходов),
чтобы `<C-o>` возвращал в буфер плагина на прежнее место, ценой того, что окно с видом занято
файлом (вид скрыт и жив, D52). Если текущее окно плавающее (буфер диалога агента), прежнее
правило D32: окно редактирования, без него — новое окно. Заменяет в D32 слова «открытие в окне
редактирования» (остальное в D32 действует).

### D55. Что остаётся всплывающим

Окно ввода сообщения (`m`), предпросмотр по `K` и буфер диалога агента (`d`, спецификация
`agent-dialogs`) остаются плавающими: первые два назвал пользователь; буфер диалога лежит
вне видов узлов и требует собственного изменения (приоритет 4), в отчёте предложен
пользователю как следующий шаг.

### D56. Размер экрана терминала задаёт окно

В условиях, когда окно вида стало обычным и его размер задаёт раскладка Neovim, учитывая,
что клиент наблюдения herdr сообщает серверу размер (`--cols`, `--rows`; в журнале сервера
клиент по умолчанию 120×40), выбрано запрашивать у сервера размер окна вида и не менять окно
по размеру кадра, чтобы эмулятор терминала Neovim не получал кадры иного размера (искажение
экрана), ценой того, что размер не отслеживает последующих изменений окна: вид открывают
заново. Поведение сервера по `--cols`/`--rows` на рабочем сервере не проверялось (по условию
задачи сервер доступен только для чтения), проверено на двойнике.

### D57. Подключение с вводом — тоже в окне

Подключение с вводом (`i`) открывается буфером терминала в том же окне по D51; выход из
подключения (`Ctrl+b q`) возвращает в окне альтернативный буфер (вид наблюдения, если
подключение открыто из него). Режим терминала включается, как раньше, при открытии.

## Risks / Trade-offs

- Скрытый вид (D52) не освобождается, пока не закрыт `q` или окно: так же ведёт себя любой
  скрытый терминальный буфер.
- Окно, в котором вид окажется после `<C-o>` из другого окна, освобождением не управляет:
  `WinClosed` привязан к окну, где вид открыт.
- Размер при изменении окна не пересогласуется (D56).

## Context

Требование пользователя (дословно): «Вывод дерева должен соответствовать такому же виду в
herdr. В качестве дочерних узлов должны отображаться только закладки и дочерние субагенты
workspace. Вспомогательные окна neovim не должны отображаться. По энтер на узле должно
отображаться то же, что отображает herdr.» Уточнения пользователя: «Bash и фоновые команды
должны отображаться как дочерние узлы того узла, в котором они запущены. Основное
требование, чтобы их вывод был виден в открывающейся панели. Если это не так, то в них нет
смысла.» Под «Bash» пользователь понимает и вызовы инструмента Bash агента и субагента, и
панели herdr с оболочкой; панели с командой остаются в дереве, кроме панелей, где на
переднем плане Neovim; панель с агентом отдельной строкой не показывается. Решение
пользователя по Enter: «Соседние панели вкладки видны в дереве. Этого достаточно. Enter на
узле дерева показывает его терминал. Никакого изменения раскладок окон не нужно.»

Прочитано: спецификации `agent-tree`, `node-view`, `claude-code-data`, `agent-dialogs`,
`session-launch`, `messaging`, `message-input`, `session-history`, `herdr-client`,
`file-references`; решения D45–D57; `docs/tree.md`, `docs/node-view.md`; код
`lua/claudr/tree/model.lua`, `lua/claudr/tree/view.lua`, `lua/claudr/view/*.lua`,
`lua/claudr/data/parse.lua`.

**Приоритеты** (порядок предпочтений на развилках): точное соответствие виду и поведению
herdr; не менять то, о чём пользователь не просил; наименьший объём дельты; без таймеров и
опроса.

### Боковая панель herdr

Пути — относительно репозитория форка herdr; факты проверены по исходникам и по ответу
рабочего сервера на `session.snapshot`.

- Боковая панель — два раздела, а не дерево (`src/client/shell/sidebar.rs:209`):
  - «spaces» — строка на каждый workspace с вложенностью по `parent_workspace_id` и
    связанным worktree (`sidebar.rs:498`, `workspace_entries`); у workspace с активной
    вкладкой не первой по счёту под строкой workspace стоит строка этой вкладки с ветвью
    `└─` (`sidebar.rs:819`, `tab_row`). Состав строки задаёт `[ui.sidebar.spaces] rows`;
    в конфигурации пользователя — значок состояния и подпись workspace. Значок — по
    `agent_status` workspace, часы строки — по `workspace_id` (`sidebar.rs:346`).
  - «agents» — строка на каждую панель с агентом (`src/client/shell/agent_sidebar.rs:239`,
    `agent_rows`), порядок «grouped» (`agent_panel_sort = "spaces"`) — порядок снимка.
    Состав строки задаёт `[ui.sidebar.agents] rows`; в конфигурации пользователя — значок
    состояния и токен `tab`: подпись вкладки агента, а у единственной вкладки без ручного
    имени — подпись workspace (`agent_sidebar.rs:279`, `labels.rs:65`, `tab_token_shown`).
    Значок — по `agent_status` панели, часы строки — по `pane_id` (`agent_sidebar.rs:390`).
- Панели без агента (оболочка, Neovim) боковая панель не показывает нигде. Субагентов и
  фоновых команд herdr не знает.
- `agent_status` вкладки в снимке — состояние её панелей с наибольшим приоритетом внимания
  (`src/app/creation.rs:209`), у workspace — то же по всем вкладкам
  (`src/workspace/aggregate.rs:61`).
- У панели с агентом в снимке рабочего сервера есть токен `input_pane` с идентификатором
  соседней панели Neovim (его ставит плагин `duty`); у самой панели Neovim
  `foreground_process = "nvim"`. Вкладки, открытые агентами для команд (подпись
  `▸ <имя>`), содержат одну панель с `bash`.

### Наблюдение за терминалом

Наблюдение (`terminal session observe`) — только по одному терминалу: цель — панель,
терминал или агент (`src/protocol/wire.rs:533`); экран терминала рисуется в размер,
заявленный клиентом наблюдения, размер терминала панели не меняется
(`src/server/headless/render.rs:761`). Наблюдения за вкладкой целиком нет.

### Вызовы инструмента Bash в данных Claude Code

Проверено на живых сессиях.

- Каждый вызов Bash (не только фоновый) пишет вывод в файл
  `<временный каталог Claude Code>/<имя каталога проекта>/<сессия>/tasks/<идентификатор
  задачи>.output`: стандартные потоки вывода и ошибок процесса команды направлены в этот
  файл. Имя каталога проекта совпадает с именем каталога транскрипта в `projects/`.
  Вызовы субагентов пишут в каталог задач сессии-владельца.
- По завершении обычного (не фонового) вызова файл удаляется. Файл фоновой команды
  остаётся. Вызов, переведённый в фон по ходу работы, сохраняет идентификатор задачи и
  файл.
- Пока вызов работает, в транскрипте его нет: запись вызова и результата появляются после
  завершения. Владельца (агент или субагент) и `description` во время работы узнать по
  транскрипту нельзя; панель известна по сессии каталога задач.
- Процесс команды — потомок процесса Claude Code; его потоки вывода указывают на файл
  задачи, в командной строке — `eval '<команда>'`, в окружении — `HERDR_PANE_ID` и
  идентификатор сессии, но не идентификатор субагента.
- Результат завершённого вызова — `toolUseResult` с `stdout`, `stderr`, `interrupted`;
  большой вывод сохраняется целиком в `tool-results/<идентификатор задачи>.txt` каталога
  сессии (`persistedOutputPath`), в тексте результата — начало вывода.
- В каталоге задач лежат также символические ссылки `<идентификатор агента>.output` на
  транскрипты субагентов; это не вызовы Bash.

### Фоновые команды: доступность вывода

Из 86 файлов вывода фоновых команд, упомянутых в транскриптах за двое суток, на месте 85;
недостающий — во временном каталоге, очищенном системой. Файл фоновой команды субагента
лежит в каталоге задач сессии-владельца. Вывода нет, когда временный каталог очищен
(перезагрузка, очистка `/tmp`) или когда в результате вызова и в уведомлении нет пути файла.

## Goals / Non-Goals

**Goals:** строки дерева совпадают по составу и виду с боковой панелью herdr там, где у
herdr есть соответствие; Enter на узле показывает его терминал или вывод; у каждого узла
команды по Enter виден вывод.

**Non-Goals:** правка herdr, его протокола и конфигурации; два раздела боковой панели в
окне дерева; экран вкладки из нескольких окон; изменение раскладки окон Neovim; режим `icons = "text"`
сверх нового знака и слова состояния вкладки.

## Decisions

Нумерация продолжает `node-view-in-window` (D50–D57).

### D58. Строки дерева: вкладки вместо панелей с агентом

*Заменяет D46 в части «панели стоят под workspace» и D49 в части знака панели с агентом.*
В условиях, когда herdr показывает агента строкой «значок состояния, подпись вкладки», а
пользователь требует в дереве только вкладки и субагентов, учитывая уточнение пользователя
о панелях с командой, выбрано: панель с агентом строкой не показывается, её несёт строка
вкладки; дети вкладки — панели с командой, кроме панелей с `foreground_process = "nvim"`,
и панели прочих агентов вкладки (D60) по номеру, затем субагенты агента вкладки, его фоновые команды и вызовы Bash; вложенный workspace
по-прежнему после вкладок родителя; единственная вкладка в режиме `icons = "herdr"`
строкой не показывается, её дети стоят под workspace (как в herdr: у единственной вкладки
без ручного имени строка агента подписана workspace), чтобы строки читались как боковая
панель herdr, ценой того, что агент без вкладки-строки виден только как workspace.
Признак Neovim — процесс на переднем плане, как назвал пользователь; токен `input_pane`
отвергнут: его ставит плагин `duty`, у других пользователей его нет, и он не скрывает
панель Neovim, открытую не как панель ввода. Панель, где агент вышел и осталась оболочка,
становится панелью с командой под своей вкладкой.

Расхождения с herdr, которые остаются: herdr не строит дерево (два раздела); панель с
командой herdr не показывает, а дерево показывает по уточнению пользователя; вкладка с
двумя агентами в herdr — две строки агентов, в дереве — строка вкладки (агент вкладки) и
под ней строка второго агента.

### D59. Строка вкладки — строка агента herdr

В условиях, когда строка агента herdr — значок `agent_status` и токен `tab`, выбрано:
строка вкладки — значок `agent_status` вкладки из снимка (приоритет внимания по панелям,
как в herdr) и подпись вкладки по прежнему правилу (D46), без знака вида; цвет — `color`
workspace; часы строки при `frame_phase = "per_row"` — по идентификатору агента вкладки
(D60), как часы строки агента herdr, без агента — по идентификатору вкладки; workspace —
по `workspace_id`, как в herdr; число ждущих запросов — агента вкладки и его субагентов, чтобы значок и анимация строки совпадали с herdr, ценой того, что у вкладки
с несколькими агентами строка показывает сводное состояние, а не состояние каждого. В
режиме `icons = "text"` строка вкладки получает состояние словом в квадратных скобках:
состояние агента ушло со строки панели на строку вкладки.

### D60. Агент вкладки и прочие агенты вкладки

В условиях, когда действия `m`, `d`, `i`, `S`, история сессий были привязаны к строке
панели с агентом, а строки больше нет, выбрано: агент вкладки — панель с агентом в фокусе,
иначе первая панель с агентом по номеру (то же правило, что «приложение» подписи вкладки);
действие, адресованное агенту, на строке вкладки (и на строке workspace со скрытой
единственной вкладкой) адресуется агенту вкладки; вкладка без агента — `m`, `d`, история
сессий сообщают, что агента нет, а `i` и `S` адресуются панели в фокусе, иначе первой.
Остальные панели с агентом той же вкладки — дочерние строки вкладки среди её панелей (по
номеру): значок состояния панели и подпись агента (`display_agent`, без него `agent`, и
заголовок терминала), их субагенты, фоновые команды и вызовы Bash — под ними, действия на
такой строке — её панели. Так любой агент достижим из дерева, а вкладка с одним агентом
не получает отдельной строки панели, ценой того, что при смене фокуса между агентами
вкладки строка агента и его дети переезжают. Строка workspace с несколькими вкладками
действий над агентом не имеет.

### D61. Enter на узле — его терминал, одним буфером

*Заменяет перечень панелей (D18, D20 в части контейнеров).* В условиях, когда пользователь
сказал: «Enter на узле дерева показывает его терминал. Никакого изменения раскладок окон не
нужно», учитывая, что наблюдение herdr есть только по одному терминалу, выбрано: Enter на
вкладке — наблюдение за терминалом агента вкладки, во вкладке без агента — за панелью в
фокусе, без неё — первой по номеру; Enter на workspace — то же для его вкладки
`active_tab_id`; на панели с командой и на строке прочего агента — терминал этой панели; на
субагенте — транскрипт; на фоновой команде и вызове Bash — вывод. Вид — один буфер в окне
по D50–D57, раскладка окон Neovim не меняется, чтобы Enter вёл себя одинаково для всех
узлов, ценой того, что панели вкладки рядом с агентом на одном экране не видны — их
показывают строки дерева.

### D62. Вызовы инструмента Bash

В условиях, когда пользователь требует видеть вызовы Bash агента и субагента с их
выводом, учитывая, что во время работы вызова в транскрипте записи нет, а вывод идёт в
файл каталога задач, выбрано: модуль данных следит за каталогом задач сессии уведомлениями
файловой системы; работающий вызов — обычный файл `.output` в каталоге задач, который не
принадлежит фоновой команде из учёта сессии; его узел стоит под вкладкой агента (владелец
во время работы неизвестен), подпись — команда из командной строки процесса, чьи потоки
вывода указывают на файл (`eval '…'`), без неё — `Bash`; удаление файла завершает узел
работающего вызова; завершённый вызов — пара «вызов Bash без `run_in_background` —
результат» в транскрипте владельца, узел под владельцем (агент вкладки или субагент),
подпись — `description`, без него — `command`, вывод — `stdout` и `stderr` результата, при
`persistedOutputPath` — файл полного вывода. Идентификатор работающего узла —
`<панель>/<идентификатор задачи>`, поэтому вызов, переведённый в фон, становится фоновой
командой с тем же узлом; завершённого — `<панель>/<идентификатор вызова>`. Так вывод
виден и во время работы, и после завершения, без опроса, ценой: работающий вызов субагента
стоит под вкладкой, а после завершения переезжает под субагента; описание во время работы
недоступно; чтение `/proc` для подписи работает только на Linux и только для сервера на
той же машине, иначе подпись `Bash`; вид работающего вызова после удаления файла
сохраняет показанное и сообщает о завершении, итог открывается Enter на завершённом узле.
Каталог задач, которого ещё нет, ждётся наблюдением за ближайшим существующим каталогом
выше по пути (как `subagents/`).

Отвергнуто: только завершённые вызовы — вывод не виден во время работы, а пользователь
поставил это главным; сопоставление работающего файла с субагентом по времени — без
признака в данных даёт ошибки при параллельных вызовах.

### D63. Узел команды без вывода не показывается

В условиях, когда пользователь считает узел команды бессмысленным без вывода, выбрано:
фоновая команда показывается, только пока её файл вывода существует (проверка при
перестроении модели и по уведомлению каталога задач об удалении); работающий вызов Bash
существует только вместе с файлом; завершённый вызов Bash показывается всегда — результат
лежит в транскрипте, даже пустой или с ошибкой отказа, чтобы каждый узел команды по Enter
давал вывод, ценой того, что фоновая команда из очищенного временного каталога исчезает из
дерева вместе со статусом и кодом выхода. Вид фоновой команды, файл которой исчез после
открытия, сообщает об этом и показывает статус и код выхода, как раньше.

### D64. Завершённые вызовы Bash — по правилу «Завершённые узлы»

В условиях, когда вызовов Bash в сессии сотни, выбрано подчинить завершённые вызовы
существующему правилу: в модели до закрытия панели владельца, в окне скрыты по умолчанию,
показ — `F` и `show_finished`, чтобы дерево не разрасталось и переключатель остался один,
ценой памяти модели на всю историю вызовов сессии. При показе завершённых в дереве могут
оказаться сотни строк; ограничение числа показанных — отдельное решение пользователя,
если понадобится.

### D65. Знаки и текстовый режим

*Дополняет D49.* Выбрано: вызов Bash — знак `🐚` после значка состояния, в режиме
`icons = "text"` — `!` (команда оболочки в Vim); панель с командой — `💻` и `$`, как раньше;
строка вкладки без знака вида, как строка агента herdr; строка прочего агента вкладки
сохраняет знак панели с агентом (символ workspace, без него `🧠`) и букву `A`.

## Risks / Trade-offs

- Подпись работающего вызова Bash зависит от `/proc`; на удалённом сервере herdr каталог
  задач лежит на другой машине, и работающие вызовы не видны.
- Формат каталога задач и удаление файла по завершении — поведение Claude Code, не
  описанное как интерфейс; изменение формата ограничивается модулем данных.

## ADDED Requirements

### Requirement: Каталог задач сессии
Каталогом задач сессии MUST считаться `<временный каталог Claude Code>/<имя каталога проекта>/<идентификатор сессии>/tasks`, где имя каталога проекта совпадает с именем каталога транскрипта сессии в `projects/`, а временный каталог Claude Code — `claude-<uid>` во временном каталоге системы. В каталоге задач лежат файлы вывода вызовов Bash сессии и её субагентов (`<идентификатор задачи>.output`) и символические ссылки на транскрипты субагентов; ссылки MUST NOT считаться файлами вывода.

#### Scenario: Ссылка на транскрипт субагента
- **WHEN** в каталоге задач лежит символическая ссылка `<идентификатор агента>.output`
- **THEN** модуль не считает её ни вызовом Bash, ни фоновой командой

### Requirement: Работающий вызов Bash
Вызовом Bash MUST считаться вызов инструмента Bash без `run_in_background: true`. Работающим вызовом MUST считаться обычный файл `.output` в каталоге задач сессии, не принадлежащий фоновой команде из записей транскрипта; запись содержит идентификатор задачи (имя файла), путь файла и, если её удалось определить, команду — из командной строки процесса, чьи потоки вывода направлены в этот файл. Вызов принадлежит сессии каталога задач. Удаление файла MUST завершать запись работающего вызова.

#### Scenario: Работающий вызов
- **WHEN** в каталоге задач сессии появляется файл `b1.output`, а фоновой команды `b1` в транскриптах нет
- **THEN** модуль отдаёт работающий вызов Bash `b1` с путём файла

#### Scenario: Процесс не найден
- **WHEN** процесс, пишущий в файл работающего вызова, определить нельзя
- **THEN** запись вызова отдаётся без команды, ошибки нет

### Requirement: Завершённый вызов Bash
Завершённым вызовом Bash MUST считаться пара «вызов — результат» в транскрипте владельца (сессии или субагента); из вызова модуль MUST брать `command` и `description`, из результата — `stdout`, `stderr`, `interrupted` и путь сохранённого полного вывода (`persistedOutputPath`), если он есть. Вызов MUST принадлежать тому владельцу, в чьём транскрипте записан.

#### Scenario: Вызов завершился
- **WHEN** файл `b1.output` удалён, в транскрипте субагента появились вызов Bash и его результат со `stdout`
- **THEN** работающего вызова `b1` больше нет, у субагента есть завершённый вызов с командой, описанием и выводом

#### Scenario: Сохранённый полный вывод
- **WHEN** результат вызова содержит `persistedOutputPath`
- **THEN** запись завершённого вызова содержит этот путь

### Requirement: Вызов, переведённый в фон
Файл работающего вызова, для которого в транскрипте появилась фоновая команда с тем же идентификатором задачи, MUST отдаваться как фоновая команда, а не как вызов Bash.

#### Scenario: Переход в фон
- **WHEN** для работающего вызова `b1` в транскрипте появляется фоновая команда `b1`
- **THEN** модуль отдаёт `b1` как фоновую команду, работающего вызова `b1` нет

## MODIFIED Requirements

### Requirement: Единый модуль чтения данных Claude Code
Все данные Claude Code (транскрипты, `meta.json` субагентов, записи фоновых команд и вызовов Bash, каталог задач, файлы вывода) MUST читаться одним модулем. Остальной код MUST получать от него записи видов «субагент», «фоновая команда», «вызов Bash» и «реплика диалога» и MUST NOT разбирать эти форматы сам. Модуль дополнительно MUST разбирать вход хука `PermissionRequest` и вложение `hook_permission_decision` транскрипта (`agent-dialogs`).

#### Scenario: Изменение формата
- **WHEN** Claude Code меняет запись транскрипта
- **THEN** правка ограничивается модулем чтения, а дерево, виды и перечни получают те же виды записей

#### Scenario: Вход хука и вложение решения
- **WHEN** приходит вход хука `PermissionRequest` или в транскрипте появляется вложение `hook_permission_decision`
- **THEN** их разбирает модуль чтения, остальной код этих форматов не разбирает

### Requirement: Состояние «оборван»
Субагент, фоновая команда или работающий вызов Bash без отметки завершения MUST получать состояние «оборван», когда модулю сообщено, что панель владельца завершила процесс или закрыта. Правило общее для субагентов, команд и вызовов, в том числе вложенных. Процесс владельца, убитый принудительно, не оставляет в транскрипте записей о своих командах: состояние определяется только этим правилом.

#### Scenario: Владелец упал
- **WHEN** у субагента нет отметки завершения и сообщено, что панель владельца закрыта
- **THEN** субагент и его фоновые команды без отметки завершения оборваны

#### Scenario: Владелец убит принудительно
- **WHEN** транскрипт владельца не содержит ни уведомления, ни результата остановки для команды, а сообщено, что процесс панели завершён
- **THEN** команда получает состояние «оборван»

#### Scenario: Работающий вызов после выхода процесса
- **WHEN** файл работающего вызова Bash остался в каталоге задач, а сообщено, что процесс панели завершён
- **THEN** вызов получает состояние «оборван»

#### Scenario: Владелец жив
- **WHEN** отметки завершения нет, а панель владельца жива
- **THEN** узел остаётся работающим

### Requirement: Слежение за изменениями
Изменения каталога сессии, `subagents/`, транскриптов, каталога задач сессии и файлов вывода MUST отслеживаться уведомлениями файловой системы (`vim.uv.new_fs_event`). Пока каталога `subagents/` нет, MUST наблюдаться каталог сессии; когда `subagents/` создан, наблюдение MUST переходить на него. Пока каталога задач нет, MUST наблюдаться ближайший существующий каталог на пути к нему; когда он создан, наблюдение MUST переходить на него. Появление и удаление файла в каталоге задач MUST уведомлять подписчиков.

#### Scenario: Первый субагент
- **WHEN** у сессии не было каталога `subagents/`, и он создаётся
- **THEN** наблюдение переходит на него, а подписчики получают нового субагента

#### Scenario: Первый вызов Bash
- **WHEN** у сессии не было каталога задач, и он создаётся вместе с файлом вывода
- **THEN** наблюдение переходит на него, а подписчики получают работающий вызов

#### Scenario: Удаление файла вывода
- **WHEN** в каталоге задач удаляется файл вывода фоновой команды
- **THEN** подписчики получают уведомление, команда помечена как не имеющая вывода

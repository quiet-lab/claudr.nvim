# code-questions Specification

## Purpose
Вопросы по коду в темах: отдельные сессии Claude Code, запущенные плагином, реестр тем, точки расширения.

## Requirements

### Requirement: Тема — отдельная сессия Claude Code
Тема вопросов по коду MUST быть отдельной сессией Claude Code, которую плагин запускает процессом `claude -p` в каталоге проекта. Тема MUST NOT занимать панель herdr и MUST NOT входить в дерево.

#### Scenario: Первый вопрос
- **WHEN** пользователь задаёт вопрос по коду
- **THEN** плагин запускает процесс `claude -p` в каталоге проекта, в дереве нового узла нет

### Requirement: Каталог проекта
Каталогом проекта MUST быть корень проекта, найденный от файла буфера по маркеру `.git`; если корня нет, каталог текущей рабочей директории Neovim.

#### Scenario: Файл в репозитории
- **WHEN** вопрос задан из буфера файла внутри репозитория git
- **THEN** процесс запускается в корне этого репозитория

### Requirement: Идентификатор сессии темы
Идентификатор сессии новой темы MUST задавать плагин при создании темы, передав его процессу при запуске; запись в реестре MUST создаваться до запуска процесса. Продолжение темы MUST использовать тот же идентификатор.

#### Scenario: Новая тема
- **WHEN** пользователь задаёт первый вопрос новой темы
- **THEN** запись реестра с идентификатором сессии создана до запуска процесса, процесс получает этот идентификатор, транскрипт сессии называется по нему

#### Scenario: Процесс не запустился
- **WHEN** процесс не удалось запустить
- **THEN** запись реестра остаётся, вопрос доступен для повторной отправки с тем же идентификатором

### Requirement: Новая тема и продолжение темы
Вопрос из буфера с кодом MUST открывать новую тему. Вопрос из окна ответа MUST продолжать тему этого окна, запуская процесс с `--resume <идентификатор сессии темы>`. Плагин MUST NOT определять тему автоматически, в том числе с помощью модели.

#### Scenario: Второй вопрос из буфера
- **WHEN** пользователь второй раз задаёт вопрос из буфера с кодом
- **THEN** создаётся новая тема с новой сессией

#### Scenario: Вопрос из окна ответа
- **WHEN** пользователь задаёт вопрос из окна ответа темы
- **THEN** процесс запускается с `--resume` и идентификатором сессии этой темы

### Requirement: Вопрос по выделению
Пользователь MUST иметь возможность задать вопрос по выделенному фрагменту: в вопрос MUST входить текст вопроса и пакет контекста от поставщиков, в котором есть путь файла, диапазон строк и текст выделения.

#### Scenario: Вопрос по выделению
- **WHEN** пользователь выделяет строки 10–20 файла `lua/foo.lua` и вводит вопрос
- **THEN** в вопрос уходят текст вопроса, путь `lua/foo.lua`, диапазон 10–20 и текст выделенных строк

### Requirement: Вопрос по файлу
Пользователь MUST иметь возможность задать вопрос по текущему файлу без выделения: в вопрос MUST входить текст вопроса и путь файла; содержимое файла MUST уходить как есть, включая несохранённые правки буфера.

#### Scenario: Вопрос по файлу
- **WHEN** пользователь вызывает вопрос по файлу и вводит текст
- **THEN** в вопрос уходят текст вопроса и путь файла с содержимым буфера

### Requirement: Ответ по мере генерации
Ответ MUST показываться в окне сбоку по мере генерации, только для чтения: процесс выдаёт потоковый вывод с частичными сообщениями, текст ответа накапливается по приращениям текста. Ввод вопроса MUST идти через `vim.ui.input`, выбор из списка — через `vim.ui.select`. Выход из Neovim MUST NOT останавливать отвечающий процесс: он дописывает ответ в транскрипт темы.

#### Scenario: Длинный ответ
- **WHEN** процесс выдаёт ответ частями, приращениями текста
- **THEN** окно сбоку дополняется новыми частями, не дожидаясь завершения процесса

#### Scenario: Вызов инструмента в ответе
- **WHEN** в потоке между приращениями текста идут записи вызова инструмента и служебные записи
- **THEN** они не попадают в текст ответа, окно показывает только накопленный текст

#### Scenario: Выход из Neovim во время ответа
- **WHEN** Neovim завершается, пока отвечающий процесс пишет ответ
- **THEN** процесс не останавливается, ответ дописывается в транскрипт темы и виден при следующем открытии темы

### Requirement: Ссылки на код в ответе
Ссылки вида `файл:строка` в тексте ответа MUST открываться переходом: к файлу и строке в окне редактирования. Клавиши перехода и предпросмотра, определение ссылки и открытие задаёт возможность `file-references` (переход соответствует её клавише открытия, по умолчанию `gd`).

#### Scenario: Переход по ссылке
- **WHEN** пользователь вызывает переход (`gd`, `file-references`) на ссылке `lua/foo.lua:42` в окне ответа
- **THEN** файл `lua/foo.lua` открывается в окне редактирования на строке 42

### Requirement: Ошибка запуска и обрыв процесса
Ошибка запуска процесса и его обрыв до окончания ответа MUST показываться в окне темы с причиной. Текст вопроса MUST оставаться доступным для повторной отправки без повторного ввода.

#### Scenario: Процесс оборвался
- **WHEN** процесс завершается с ошибкой до конца ответа
- **THEN** окно темы показывает полученную часть ответа и причину, вопрос можно отправить повторно

#### Scenario: Claude Code не найден
- **WHEN** исполняемого файла `claude` нет
- **THEN** окно темы показывает ошибку запуска

### Requirement: Один отвечающий процесс на тему
В теме в каждый момент MUST работать не больше одного отвечающего процесса: два одновременных продолжения одной сессии разветвляют её историю. Вопрос, заданный в теме до конца предыдущего ответа, MUST вставать в очередь этой темы и уходить после завершения процесса темы.

#### Scenario: Вопрос во время ответа
- **WHEN** пользователь задаёт вопрос в теме, пока процесс этой темы ещё отвечает
- **THEN** вопрос встаёт в очередь темы, второй процесс не запускается, после завершения ответа вопрос уходит продолжением той же сессии

#### Scenario: Два вопроса подряд в одной теме
- **WHEN** в очереди темы два вопроса
- **THEN** они уходят по одному, в порядке постановки

### Requirement: Несколько тем одновременно
Несколько тем MAY отвечать одновременно; у каждой темы MUST быть свой процесс и своё окно ответа, ответы MUST NOT смешиваться.

#### Scenario: Два вопроса подряд
- **WHEN** пользователь задаёт вопрос в новой теме, пока другая тема ещё отвечает
- **THEN** обе темы получают ответы каждая в своём окне

### Requirement: Реестр тем
Плагин MUST хранить в каталоге состояния Neovim запись о каждой теме: идентификатор сессии, каталог проекта, заголовок (начало первого вопроса), режим, файл и символ, откуда задан вопрос, время создания и последнего обращения. Реестр MUST переживать перезапуск Neovim.

#### Scenario: Новая тема
- **WHEN** создана тема из буфера `lua/foo.lua` с курсором в функции `bar`
- **THEN** в реестре появляется запись с идентификатором сессии, каталогом проекта, заголовком, режимом, файлом `lua/foo.lua`, символом `bar` и временем создания

#### Scenario: Новое обращение
- **WHEN** пользователь продолжает тему
- **THEN** время последнего обращения в её записи обновляется

### Requirement: Восстановление окна темы
Содержимое темы MUST браться из транскрипта её сессии, окно темы MUST восстанавливаться из него без повторного запуска процесса. Тема, транскрипт которой удалён, MUST оставаться в перечне с пометкой «содержимое недоступно».

#### Scenario: Открытие закрытой темы
- **WHEN** пользователь открывает тему после перезапуска Neovim
- **THEN** окно показывает вопросы и ответы темы из транскрипта

#### Scenario: Транскрипт удалён
- **WHEN** транскрипта сессии темы нет
- **THEN** тема остаётся в перечне с пометкой «содержимое недоступно»

### Requirement: Возврат к теме
Возврат к теме MUST быть возможен через перечень тем проекта и команду «последняя тема», открывающую тему с самым поздним временем последнего обращения. Перечень тем MUST быть отдельным от перечня сессий инстансов.

#### Scenario: Последняя тема
- **WHEN** пользователь вызывает «последняя тема»
- **THEN** открывается окно темы проекта с самым поздним временем последнего обращения

### Requirement: Модель и инструменты
Модель отвечающего процесса MUST задаваться настройкой `model` со значением по умолчанию `sonnet`. Отвечающий процесс MUST получать только инструменты чтения, если режим не задаёт иного набора.

#### Scenario: Настройки по умолчанию
- **WHEN** пользователь не менял настроек
- **THEN** процесс запускается с моделью `sonnet` и только инструментами чтения

### Requirement: Режимы
Режим MUST быть именованным набором: наставление агенту (дополнение к системному запросу), модель, набор инструментов. Встроенный режим один — «вопрос по коду». Дополнительные режимы MUST регистрироваться пользователем или другим плагином.

#### Scenario: Свой режим
- **WHEN** зарегистрирован режим с наставлением и набором инструментов, и вопрос задан в этом режиме
- **THEN** процесс получает наставление как дополнение к системному запросу и заданный набор инструментов

### Requirement: Поставщики контекста
Поставщик контекста MUST быть функцией, которая по буферу и выделению возвращает пакет контекста. Встроенный общий поставщик MUST давать файл, строки, выделенный текст, охватывающий узел tree-sitter, определение и описание символа по запросам языкового сервера; отсутствие подключённого сервера MUST NOT быть ошибкой. Дополнительные поставщики MUST регистрироваться по типу файла и дополнять пакет общего поставщика.

#### Scenario: Нет языкового сервера
- **WHEN** к буферу не подключён языковой сервер
- **THEN** пакет содержит файл, строки, текст выделения и узел tree-sitter, без определения и описания символа, ошибки нет

#### Scenario: Поставщик для типа файла
- **WHEN** для типа файла буфера зарегистрирован дополнительный поставщик
- **THEN** его данные добавляются к данным общего поставщика

### Requirement: Источник знаний
Источником знаний MUST быть необязательный MCP-сервер, заданный настройкой для проекта и передаваемый отвечающему процессу. Без него плагин MUST работать.

#### Scenario: Источник задан
- **WHEN** для проекта настроен MCP-сервер
- **THEN** отвечающий процесс получает его при запуске

#### Scenario: Источника нет
- **WHEN** MCP-сервер для проекта не задан
- **THEN** вопросы по коду работают без него

### Requirement: Ответвление от базовой сессии
Плагин MUST принимать необязательную настройку `fork_from_base`, по умолчанию выключенную. Ответвления новой темы от базовой сессии плагин MUST NOT делать при любом значении настройки: тема — новая сессия. При включённой настройке плагин MUST один раз за сеанс Neovim предупредить, что ответвление не поддерживается.

#### Scenario: Настройка по умолчанию
- **WHEN** пользователь не менял настроек и открывает новую тему
- **THEN** тема — новая сессия, не ответвление

#### Scenario: Включённая настройка
- **WHEN** задано `fork_from_base = true`, и пользователь открывает две новые темы
- **THEN** обе темы — новые сессии, не ответвления; плагин один раз предупреждает, что ответвление не поддерживается

### Requirement: Отсутствие таймеров и опроса
Получение ответа MUST идти по событиям (вывод и выход процесса, уведомления файловой системы); таймеры и опрос MUST NOT использоваться.

#### Scenario: Ожидание ответа
- **WHEN** ответ ещё не получен
- **THEN** плагин не выполняет периодических проверок

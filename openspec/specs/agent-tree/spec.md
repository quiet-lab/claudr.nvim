# agent-tree Specification

## Purpose
Дерево workspace, вкладок, панелей, субагентов и фоновых команд с состояниями «работает», «завершён», «оборван».

## Requirements

### Requirement: Состав дерева
Дерево MUST содержать все workspace сервера herdr с вложенностью по `parent_workspace_id`, в каждом workspace — его вкладки в порядке `number`, вложенные workspace — после вкладок родителя. Под вкладкой MUST находиться, в этом порядке: её панели с командой, кроме панелей с `foreground_process = "nvim"`, и панели прочих агентов вкладки в порядке `number`; субагенты агента вкладки; его фоновые команды; его вызовы Bash. Вкладки и панели MUST входить в дерево независимо от того, кем они созданы.

#### Scenario: Вложенный workspace
- **WHEN** в снимке workspace `w2` имеет `parent_workspace_id` равный `w1`
- **THEN** `w2` находится в дереве под `w1` после вкладок `w1`

#### Scenario: Агент открыл новую вкладку
- **WHEN** агент в панели создаёт вкладку и запускает в ней другого агента
- **THEN** строка вкладки с состоянием агента появляется в дереве без действий пользователя, строки панели агента нет

#### Scenario: Вкладка с агентом и Neovim
- **WHEN** во вкладке `w1:t2` панель `w1:p1` с агентом и панель `w1:p2` с `foreground_process = "nvim"`
- **THEN** под строкой `w1:t2` нет строк `w1:p1` и `w1:p2`

#### Scenario: Вкладка с оболочкой
- **WHEN** во вкладке с агентом есть панель с `bash` в каталоге `/src`
- **THEN** под строкой вкладки стоит строка панели с `bash` и `/src`

#### Scenario: Единственная вкладка
- **WHEN** у workspace `w1` одна вкладка `w1:t1` с панелью агента `w1:p1` и его субагентом
- **THEN** строки `w1:t1` и `w1:p1` нет, субагент стоит под строкой `w1`; в режиме `icons = "text"` строка `w1:t1` есть, субагент под ней

### Requirement: Виды панелей
Узлом дерева MUST быть панель с командой (в снимке не задан `agent`) без Neovim на переднем плане и панель с агентом, которая не является агентом вкладки. Подпись панели с командой MUST содержать `foreground_process` и `cwd`.

#### Scenario: Панель с командой
- **WHEN** в панели без агента работает `cargo` в каталоге `/src`
- **THEN** узел панели имеет подпись с `cargo` и `/src`

#### Scenario: Панель с агентом
- **WHEN** в снимке у единственной панели с агентом вкладки `agent = "claude"`
- **THEN** узла панели нет, вкладка панели показывает её состояние

### Requirement: Агенты других видов
Агент не Claude Code MUST показываться только состоянием строки своей вкладки, без субагентов, фоновых команд и вызовов Bash.

#### Scenario: Агент не Claude Code
- **WHEN** во вкладке работает агент другого вида
- **THEN** строка вкладки показывает его состояние, дочерних узлов субагентов, фоновых команд и вызовов Bash этого агента нет

### Requirement: Субагенты агента вкладки
Под строкой вкладки MUST находиться субагенты сессий её агентов Claude Code, полученные от модуля `claude-code-data` по `agent_session.value` их панелей. Субагент первого уровня MUST быть дочерним узлом вкладки, вложенный (с `parentAgentId`) — дочерним узлом своего родителя. Подпись субагента MUST состоять из описания (без него — первой строки задания, не длиннее 60 символов) и `agentType` в скобках; без описания и задания — из `agentType`, без всего — из идентификатора.

#### Scenario: Вложенные субагенты
- **WHEN** субагент B имеет `parentAgentId`, равный идентификатору субагента A
- **THEN** B находится под A, A — под вкладкой агента-владельца

#### Scenario: Субагент без описания
- **WHEN** у субагента нет описания, задание начинается строкой `Проверить ветку`, `agentType = "general-purpose"`
- **THEN** подпись — `Проверить ветку (general-purpose)`, а без задания — `general-purpose`

### Requirement: Агент без известной сессии
Агент вкладки, для которого транскрипт не найден или `agent_session` не задан, MUST показываться без субагентов, фоновых команд и вызовов Bash; когда сессия становится известна (`pane.updated`), они MUST появляться.

#### Scenario: Сессия ещё не известна
- **WHEN** у панели агента вкладки нет `agent_session`
- **THEN** строка вкладки показывается без дочерних узлов этой сессии, а после `pane.updated` с заполненным `agent_session` дерево получает субагентов сессии

### Requirement: Фоновые команды
Под владельцем (строкой вкладки его агента или субагентом) MUST находиться его фоновые команды: команда MUST находиться под тем владельцем, в чьём транскрипте записан её вызов; команда агента вкладки — под строкой вкладки. Подпись команды MUST содержать `description` (при отсутствии — `command`). Видимость команды — по требованию «Узел команды с выводом».

#### Scenario: Команда агента
- **WHEN** в транскрипте сессии агента вкладки есть вызов фоновой команды, её файл вывода существует
- **THEN** под строкой вкладки есть узел команды с подписью из `description`

#### Scenario: Команда субагента
- **WHEN** вызов фоновой команды записан в транскрипте субагента
- **THEN** узел команды находится под узлом этого субагента, а не под вкладкой

### Requirement: Состояния субагентов и команд
Субагент, фоновая команда и вызов Bash MUST иметь одно из состояний «работает», «завершён», «оборван», выводимое по правилам `claude-code-data`. Код выхода завершённой фоновой команды MUST показываться в подписи; остановленный (статус `killed`) показывается как «завершён» с пометкой остановки; прерванный вызов Bash — «завершён» с пометкой прерывания.

#### Scenario: Работающий субагент
- **WHEN** у субагента нет отметки завершения, а панель владельца жива
- **THEN** состояние субагента «работает»

#### Scenario: Завершение фоновой команды
- **WHEN** модуль сообщает отметку завершения команды с кодом выхода 0
- **THEN** состояние команды «завершён», подпись содержит код выхода 0

#### Scenario: Остановленная команда
- **WHEN** модуль сообщает, что команда остановлена
- **THEN** состояние команды «завершён», подпись содержит пометку остановки

#### Scenario: Упавший владелец
- **WHEN** у субагента нет отметки завершения и приходит `pane_exited` панели владельца
- **THEN** субагент, его команды без отметки завершения и работающие вызовы Bash панели получают состояние «оборван»

### Requirement: Завершённые узлы
Завершённые субагенты, фоновые команды и вызовы Bash MUST оставаться в модели дерева с состоянием «завершён» до закрытия панели владельца, но в окне дерева MUST быть скрыты по умолчанию. Показ завершённых узлов MUST переключаться командой; состояние переключателя — настройка `show_finished` со значением по умолчанию «скрывать».

#### Scenario: Завершённый узел остаётся
- **WHEN** субагент завершён, а панель владельца жива
- **THEN** узел остаётся в модели с состоянием «завершён», даже когда в окне дерева он не показан

#### Scenario: Скрыты по умолчанию
- **WHEN** плагин настроен без `show_finished`
- **THEN** завершённые субагент, команда и вызов Bash в окне дерева не показываются

#### Scenario: Показ по команде
- **WHEN** пользователь переключает показ завершённых узлов при настройке по умолчанию
- **THEN** завершённые субагенты, команды и вызовы Bash появляются в дереве

#### Scenario: Скрытие завершённых
- **WHEN** показ включён, у вкладки есть работающий субагент и оборванная команда, и пользователь переключает показ
- **THEN** завершённые субагенты, команды и вызовы Bash скрываются, работающий и оборванный остаются

#### Scenario: Закрытие панели владельца
- **WHEN** панель агента-владельца закрыта
- **THEN** узлы субагентов, команд и вызовов Bash этой панели исчезают из модели вместе с ней

### Requirement: Обновление по событиям
Дерево MUST обновляться по событиям: структура, состояния вкладок и панели с командой — по событиям herdr, субагенты, фоновые команды и вызовы Bash — по уведомлениям модуля `claude-code-data`. Дерево MUST NOT использовать таймеры и периодическое чтение, кроме таймера кадров анимации («Анимация состояний»), который MUST NOT читать сокет и файлы.

#### Scenario: Новый субагент
- **WHEN** сессия запускает субагента и модуль сообщает о нём
- **THEN** узел субагента появляется в дереве без действий пользователя

#### Scenario: Новый вызов Bash
- **WHEN** агент вкладки начинает вызов Bash и модуль сообщает о файле его вывода
- **THEN** узел вызова появляется под вкладкой без действий пользователя

#### Scenario: Ничего не происходит
- **WHEN** событий herdr и файловой системы нет, а анимируемых узлов на экране нет
- **THEN** плагин не читает ни сокет, ни файлы Claude Code, и ни один таймер не заведён

#### Scenario: Таймер кадров не читает данные
- **WHEN** таймер кадров срабатывает
- **THEN** плагин не обращается к сокету herdr и к файлам Claude Code, модель дерева не меняется

### Requirement: Значки узлов
Каждый узел в окне дерева MUST начинаться значком: workspace и вкладка — значком состояния `agent_status` без знака вида; строка прочего агента вкладки — значком состояния и знаком символа workspace (без него `🧠`); панель с командой — знаком `💻`; субагент, фоновая команда и вызов Bash — значком состояния и знаком `🤖`, `🔧` или `🐚`. Значок, источника которого нет, MUST опускаться без ошибки.

#### Scenario: Панель с агентом
- **WHEN** в снимке у панели `agent = "claude"`, `agent_status = "idle"`, у её workspace `tokens.symbol = "S1"`
- **THEN** строки панели нет; строка её вкладки начинается значком состояния вкладки, за ним подпись без знака вида

#### Scenario: Панель с командой
- **WHEN** в панели нет агента, на переднем плане `cargo`
- **THEN** строка узла начинается знаком `💻` без значка состояния

#### Scenario: Субагент и команда
- **WHEN** у агента вкладки есть работающий субагент, работающий вызов Bash и завершённая команда, показ завершённых включён
- **THEN** строка субагента содержит значок `working` и знак `🤖`, строка вызова — значок `working` и знак `🐚`, строка команды — значок `done` и знак `🔧`

#### Scenario: Состояния нет
- **WHEN** у вкладки в снимке нет поля `agent_status`
- **THEN** строка вкладки показывается без значка состояния

### Requirement: Подписи workspace и вкладок
Подпись workspace MUST состоять из символа `tokens.symbol` и `label` через пробел; без токена или при `label`, начинающемся с символа, — из `label`. Подпись вкладки MUST быть её `label`, если он отличен от номера вкладки, во вкладке есть агент и он не повторяет подпись workspace; иначе — «<символ> <место> · <приложение>» без недостающих частей, без места и приложения — `label`. Подписи workspace и вкладок MUST иметь цвет `tokens.color` (`#RGB`/`#RRGGBB`), иначе цвет обычный.

#### Scenario: Символ и цвет
- **WHEN** у workspace `label = "demo"`, `tokens = {symbol = "S1", color = "#336699"}`
- **THEN** подпись — `S1 demo`, она и подписи его вкладок окрашены `#336699`

#### Scenario: Токенов нет
- **WHEN** у workspace в снимке нет `tokens`
- **THEN** подпись — `label`, цвет подписи обычный

#### Scenario: Не цвет
- **WHEN** `tokens.color = "red"`
- **THEN** подписи показываются обычным цветом, ошибки нет

#### Scenario: Вкладка без имени
- **WHEN** у вкладки `number = 1`, `label = "1"`, в ней панель агента `opus` с каталогом `/x/proj` вне репозитория, символ workspace `S1`
- **THEN** подпись вкладки — `S1 proj · opus`

#### Scenario: Ручное имя без агента
- **WHEN** у вкладки `label = "▸ notes"`, в ней только оболочка `bash` с каталогом `/x/notes`
- **THEN** подпись вкладки — `S1 notes · bash`

#### Scenario: Имя повторяет workspace
- **WHEN** вкладка с агентом названа так же, как её workspace
- **THEN** подпись вкладки автоматическая, дубля подписи workspace нет

### Requirement: Значки состояний
Значок состояния MUST браться из таблицы значков herdr («Значки состояний из конфигурации herdr»): `idle`, `working`, `blocked`, `done`, `unknown`. Состояние субагента и команды MUST отображаться так: «работает» — как `working`, «завершён» — как `done`, «оборван» — как `unknown`. Неизвестное значение `agent_status` MUST показываться значком `unknown` и значением в подписи.

#### Scenario: Значки по таблице
- **WHEN** в таблице `working` — кадры `a`, `b`, `blocked` — `x`, а панели в состояниях `working` и `blocked`
- **THEN** строки начинаются кадром `a` (или `b`) и значком `x`

#### Scenario: Состояние done
- **WHEN** приходит `pane.agent_status_changed` с `agent_status = done`
- **THEN** узел показывает значок `done`

#### Scenario: Состояние субагента
- **WHEN** субагент «оборван»
- **THEN** его строка начинается значком `unknown`

#### Scenario: Неизвестное значение
- **WHEN** сервер присылает состояние `paused`
- **THEN** узел показывает значок `unknown` и `paused` в подписи

### Requirement: Анимация состояний
Таймер кадров MUST быть заведён, пока одновременно выполнено: буфер дерева показан в окне текущей вкладки Neovim, и среди показанных узлов (не свёрнутых и не скрытых) есть узел со значком из нескольких кадров. Иначе таймер MUST быть остановлен. Срабатывание MUST перепроверять эти условия.

#### Scenario: Таймер заведён
- **WHEN** дерево показано, а у показанной вкладки состояние `working` с несколькими кадрами
- **THEN** таймер кадров заведён

#### Scenario: Нет анимируемых узлов
- **WHEN** показаны только узлы в состояниях с одним кадром
- **THEN** таймер не заведён

#### Scenario: Окно закрыто
- **WHEN** окно дерева закрыто или в текущей вкладке дерева нет
- **THEN** таймер остановлен, и заводится заново при показе дерева с анимируемым узлом

#### Scenario: Анимируемый узел скрыт
- **WHEN** единственный узел в состоянии `working` свёрнут вместе с родителем
- **THEN** таймер остановлен, а разворачивание заводит его снова

#### Scenario: Состояние изменилось
- **WHEN** событие переводит последний `working` в `idle`, затем другое — `idle` в `working`
- **THEN** после первого таймер остановлен, после второго заведён

### Requirement: Единственная вкладка workspace
В режиме `icons = "herdr"` единственная вкладка workspace MUST NOT показываться строкой: её дочерние узлы MUST стоять прямо под workspace, а строка workspace MUST нести состояние и действия этой вкладки.

#### Scenario: Одна вкладка
- **WHEN** у workspace `w1` одна вкладка `w1:t1` с агентом и панелью с командой `cargo`
- **THEN** под строкой `w1` стоит строка панели `cargo`, строки `w1:t1` нет

### Requirement: Ключ часов строки
Ключ часов строки MUST быть: у строки вкладки — идентификатор панели агента вкладки (как у строки агента herdr), без агента — идентификатор вкладки; у workspace — `workspace_id`; у остальных узлов — идентификатор узла.

#### Scenario: Строка вкладки с агентом
- **WHEN** `frame_phase = "per_row"`, а агент вкладки `w1:t1` — панель `w1:p1` в состоянии `working`
- **THEN** кадр строки `w1:t1` в любой момент совпадает с кадром строки с ключом `w1:p1`

### Requirement: Кадр анимации
Кадр значка MUST быть функцией монотонных часов и часов строки, как в herdr: при `frame_phase = "per_row"` период строки — период состояния, умноженный на коэффициент от `1 − spread` до `1 + spread`, а сдвиг начала — в пределах круга кадров, оба по ключу строки; иначе сдвиг 0 и период состояния. Ключ строки — «Ключ часов строки». Номер кадра — целая часть от (время + сдвиг) / период по модулю числа кадров. Смена кадра MUST менять только метки значков, не текст буфера, модель и курсор.

#### Scenario: Смена кадра
- **WHEN** кадры общие и срабатывание вызвано напрямую с временем, больше прежнего на один период
- **THEN** у каждой строки `working` показан следующий кадр, по кругу после последнего

#### Scenario: Кадр по часам
- **WHEN** кадры общие и срабатывание вызвано со временем, равным пяти периодам, а кадров три
- **THEN** показан кадр с номером 2 (счёт с нуля)

#### Scenario: Кадры строк со сдвигом
- **WHEN** `frame_phase = "per_row"`, `frame_speed_spread = { working = 0.10 }`, а две вкладки с агентами в панелях `w1:p1` и `w1:p2` в состоянии `working`
- **THEN** часы их строк совпадают с часами строк агентов herdr для `w1:p1` и `w1:p2`, кадры строк в разные моменты различаются, а таймер один и стоит на ближайшей границе среди строк

#### Scenario: Только значки
- **WHEN** срабатывание сменило кадр
- **THEN** строки буфера, список узлов и положение курсора прежние, изменены только метки значков анимируемых строк

### Requirement: Режим без значков
Настройка `icons` MUST принимать `"herdr"` (по умолчанию) и `"text"`. При `"text"` узлы MUST показываться буквенными обозначениями (`W` — workspace, `T` — вкладка, `A` — прочий агент вкладки, `$` — панель с командой, `S` — субагент, `&` — фоновая команда, `!` — вызов Bash); вкладка, прочий агент, субагент, фоновая команда и вызов Bash — с состоянием словом в квадратных скобках; значки и цвет workspace MUST NOT показываться, таймер кадров MUST NOT заводиться.

#### Scenario: Текстовый режим
- **WHEN** настроено `icons = "text"` и у вкладки `agent_status = working`
- **THEN** строка вкладки начинается `T`, содержит `[working]`, значка и таймера нет

#### Scenario: Режим по умолчанию
- **WHEN** `icons` не задана
- **THEN** узлы показываются значками herdr

### Requirement: Состояние вкладки
Строка вкладки MUST показывать состояние `agent_status` вкладки из снимка herdr (`unknown`, `idle`, `working`, `blocked`, `done`) и MUST менять его по перечитанному снимку после `pane.agent_status_changed` любой панели вкладки. Неизвестное значение MUST показываться как есть. Строка workspace со скрытой единственной вкладкой MUST показывать состояние workspace.

#### Scenario: Агент ждёт ответа
- **WHEN** приходит `pane.agent_status_changed` с `agent_status = blocked` для панели с агентом вкладки `w1:t2`
- **THEN** строка `w1:t2` показывает состояние `blocked`

#### Scenario: Агент вышел
- **WHEN** агент вкладки завершил работу, и панель вернулась к оболочке (`agent` не задан)
- **THEN** под вкладкой нет субагентов, фоновых команд и вызовов Bash этой сессии, а панель стоит под вкладкой как панель с командой

### Requirement: Ждущие запросы вкладки
Строка вкладки MUST показывать число ждущих запросов агента вкладки и его субагентов, строка прочего агента — его и его субагентов (`agent-dialogs`, «Перечень ждущих запросов»).

#### Scenario: Ждущие запросы
- **WHEN** у агента вкладки в `blocked` ждут два запроса диалога
- **THEN** строка вкладки показывает состояние `blocked` и число ждущих запросов — два

### Requirement: Агент вкладки
Агентом вкладки MUST считаться её панель с агентом в фокусе, без неё — первая по номеру панель с агентом; отдельной строкой она MUST NOT показываться, её состояние несёт строка вкладки. Действие над агентом (сообщение, клавиши, диалог, история сессий, подключение с вводом, история панели) на строке вкладки MUST адресоваться панели агента вкладки; на строке workspace со скрытой единственной вкладкой — агенту этой вкладки.

#### Scenario: Два агента во вкладке
- **WHEN** во вкладке панели с агентом `w1:p1` и `w1:p3`, фокус на `w1:p3`, пользователь вызывает сообщение на строке вкладки
- **THEN** окно ввода открывается для `w1:p3`

### Requirement: Прочие агенты вкладки
Панель с агентом, которая не является агентом вкладки, MUST быть дочерней строкой вкладки среди её панелей (по номеру): значок состояния `agent_status` панели, знак символа workspace (без него `🧠`) и подпись — `display_agent` (без него `agent`) и заголовок терминала. Субагенты, фоновые команды и вызовы Bash этого агента MUST стоять под его строкой, действия над агентом на ней MUST адресоваться этой панели. Вкладка с одним агентом строки панели агента MUST NOT иметь.

#### Scenario: Второй агент вкладки
- **WHEN** во вкладке `w1:t1` панели с агентом `w1:p1` (в фокусе) и `w1:p3` (`display_agent = "opus"`), у `w1:p3` есть субагент
- **THEN** под строкой `w1:t1` стоит строка `w1:p3` с подписью, начинающейся `opus`, субагент — под ней; строки `w1:p1` нет

#### Scenario: Сообщение второму агенту
- **WHEN** пользователь вызывает сообщение на строке `w1:p3`
- **THEN** окно ввода открывается для `w1:p3`

### Requirement: Вкладка без агента
Во вкладке без агента действия, которым нужен агент (сообщение, клавиши, диалог, история сессий), MUST сообщать, что агента нет; подключение с вводом и история панели MUST адресоваться панели в фокусе, без неё — первой по номеру.

#### Scenario: Вкладка без агента
- **WHEN** во вкладке только панель `w1:p4` с `bash`, пользователь вызывает сообщение, затем подключение с вводом на строке вкладки
- **THEN** сообщение не отправляется, плагин сообщает, что агента нет; подключение с вводом открывается к `w1:p4`

### Requirement: Вызовы Bash
Под владельцем (агентом вкладки или субагентом) MUST находиться его вызовы инструмента Bash, выполненные не в фоне (`claude-code-data`, «Работающий вызов Bash», «Завершённый вызов Bash»). Работающий вызов MUST находиться под строкой вкладки своего агента: владелец во время работы неизвестен. Завершённый вызов MUST находиться под тем владельцем, в чьём транскрипте записан вызов.

#### Scenario: Работающий вызов субагента
- **WHEN** субагент агента вкладки `w1:t1` выполняет вызов Bash, файл его вывода появился в каталоге задач сессии
- **THEN** узел вызова в состоянии «работает» стоит под `w1:t1`

#### Scenario: Завершение вызова субагента
- **WHEN** вызов завершился, файл удалён, в транскрипте субагента появились вызов и результат с `description = "Сборка"`
- **THEN** узел работающего вызова исчезает, под субагентом появляется завершённый узел с подписью `Сборка`, скрытый при настройке по умолчанию

### Requirement: Подпись и смена вида вызова Bash
Подпись работающего вызова Bash MUST быть его командой; завершённого — `description`, без него — `command`. Вызов, переведённый в фон, MUST становиться фоновой командой с тем же узлом. Узел работающего вызова MUST исчезать вместе с записью работающего вызова (`claude-code-data`, «Завершение процесса вызова»); открытый вид его вывода MUST сохранять показанное.

#### Scenario: Подпись работающего вызова
- **WHEN** работает вызов Bash с командой `make all`
- **THEN** подпись узла — `make all`

#### Scenario: Подпись без команды
- **WHEN** процесс файла вывода в каталоге задач определить нельзя
- **THEN** узла вызова нет, строки `Bash` без команды в дереве нет

#### Scenario: Перевод в фон
- **WHEN** работающий вызов переведён в фон, и в транскрипте появилась фоновая команда с тем же идентификатором задачи
- **THEN** узел остаётся на месте строкой фоновой команды

#### Scenario: Прерванный вызов в дереве
- **WHEN** открыт вид вывода работающего вызова, вызов прерван, процесс завершился, а файл остался
- **THEN** после записи результата в транскрипт узла вызова нет, вид сохраняет показанный вывод

### Requirement: Узел команды с выводом
Узел фоновой команды или вызова Bash MUST показываться в дереве, только если его вывод можно показать (`node-view`): у фоновой команды — пока существует её файл вывода; у работающего вызова Bash — пока существует его файл вывода; завершённый вызов Bash — всегда (результат записан в транскрипте). Наличие файла MUST проверяться при перестроении модели и по уведомлению файловой системы об удалении файла.

#### Scenario: Файл фоновой команды удалён
- **WHEN** временный каталог очищен, и файла вывода завершённой фоновой команды нет
- **THEN** узла команды в дереве нет, даже при включённом показе завершённых

#### Scenario: Пустой результат
- **WHEN** завершённый вызов Bash вернул пустой вывод
- **THEN** узел вызова есть в модели, по Enter вид сообщает, что вывод пуст
